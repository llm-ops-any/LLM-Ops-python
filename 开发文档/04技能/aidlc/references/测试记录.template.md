## 1. 逐 AC 核对

> **每条 AC 一行，三态必选其一**。写「通过」而不给证明方式的，视为未验。

| AC | 状态 | 证明方式 | 证据 |
|---|---|---|---|
| AC-01 | ✅ 已验 | 真实浏览器观察 + 截图 | `证据/截图/ac-01.png` |
| AC-02 | ✅ 已验 | 只读代码核对 `xxx.ts:123`，分支未被改动 | —（静态项无需截图） |
| AC-03 | ⛔ 未验 | 依赖的设备不在手边 | — |
| AC-04 | — 不适用 | 本轮不涉及 | — |

状态只用四个：`✅ 已验` / `⛔ 未验` / `— 不适用` / `⏸ 待 PO 复核`。

## 2. `仅静态` 档位怎么写

策略是 `仅静态` 时，**本文件只允许出现三类内容**（见 `命名对照表.md` 第七节）：

1. **语法校验看了哪些文件**：只读走查了哪几个文件、编辑器诊断几错误几警告；
   写「未执行校验命令」，**不要**写"跑过 build / lint / tsc / typecheck"。
2. **人工测试走了哪些路径**：PO 或自己在浏览器点的具体路径（可复现的操作序列）。
3. **未覆盖什么**：写不出这条，等于宣称测试完整。

**禁止措辞**：`测试通过`、`验证成功`、`全部通过`、`无问题`。

| 检查项 | 结果 |
|---|---|
| 只读代码走查 | 覆盖 `a.ts` 的 `fnX()`、`b.ts` 的常量 Y；未逐行读全文件 |
| 编辑器诊断 | `a.ts` 0 错误 0 警告；`b.ts` 未打开 |
| 自动化测试 | **未做**（项目未接测试框架） |
| 构建 / lint / dev / 测试脚本 | **未执行**（`仅静态` 档不跑命令） |

## 3. 人工复核步骤

> 给 PO 的，**写得能照着点**。一条 AC 至少一个动作，「看一下」不算步骤。

1. 打开 ___ → 点 ___ → 进入 ___，确认 ___（对应 AC-0X）
2. 对照 ___ 模式，两边 ___ 应一致
3. 退出 → 再次进入，确认 ___ 不累积 / 不残留（对应 AC-0Y）

## 4. 未覆盖（必填）

> 这是 `04-风险.md` 里「测试档位的代价」那部分，**不是**项目级风险。

- 未在浏览器实测：___（哪些视觉 / 数值项只能人眼判断）
- 未验证线上数据：___（服务端存的配置、保存视角实际取值）
- 未覆盖的回归面：___（靠读代码推断"没影响"的地方，列出未实跑的分支）
- 因此**不能宣称**：___
