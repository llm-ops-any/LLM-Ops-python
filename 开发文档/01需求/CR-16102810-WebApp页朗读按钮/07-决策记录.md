# CR-16102810 决策记录

## D-01 不改 `/audio/message-to-audio` 的鉴权

- **担心**：WebApp 是匿名分享页，朗读接口要 `message.created_by == account.id`，会不会过不了？
- **核实**：`web_app_chat` 本身带 `@login_required`，且 `Message.created_by = current_user.id`。
  ⇒ WebApp 对话与朗读是**同一个登录用户**，现有校验天然成立。
- **决策**：一行校验都不动。
- **被否**：为 WebApp 放宽成"按 token 校验"——那等于开一个无鉴权的消息读取口子，**不能做**。

## D-02 只返回 `enable / voice / auto_play` 三个字段，不下发完整配置

- **理由**：`text_to_speech` 将来可能加字段，但前端只需要这三个；多余字段暴露配置细节没有收益。

## D-03 不做自动播放（`auto_play` 暂不实现）

- **事实**：`auto_play` 从 `CR-16102803` 起就只是配置项，调试页与首页都没实现自动播放。
- **决策**：本 CR 保持一致，只补按钮。
- **理由**：自动播放涉及「浏览器自动播放策略」（Chrome 要求用户交互后才能播），需要额外处理被拦截的降级提示，属独立体验优化。

## D-04 不改 `AiMessage`，只在 `IndexView` 传 prop

- **理由**：组件已具备 `message_id` + `enable_tts` 两个入口（`CR-16102803` 设计时就留好了），
  这次只是调用方没传。**改组件是多余动作**，容易引入回归。
