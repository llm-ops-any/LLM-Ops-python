# 构建说明 · CR-16102600

> 本项目最经典的坑：改了代码不重建镜像等于没改。下面是从改完代码到线上生效的完整动作，按顺序执行。

## 一、构建与重启（实际执行记录 2026-10-26）

```bash
cd docker

# 1. 后端（代码 + 模型 YAML 都烘焙进镜像）
docker compose --env-file .env build llmops-api
# → Image llmops-api:0.1.0 Built

# 2. 后端与队列一起重建容器（Celery 用同一个镜像，也必须重启，否则任务里还是旧凭证）
docker compose --env-file .env up -d llmops-api llmops-celery

# 3. ⚠️ 立刻重启 nginx，不要留到最后（本项目硬约束：重建 api 后 nginx 仍缓存旧容器 IP ⇒ 全站 502）
docker restart llmops-nginx

# 4. 前端（设置页改动在 ui/）
docker compose --env-file .env build llmops-ui
docker compose --env-file .env up -d llmops-ui
```

> 2026-10-26 事故复盘：第 3 步我曾挪到最后、且在完成自测后才想起 ⇒ 浏览器打开 `/home` 全站 502。
> **判据（先看这个，别翻 api 日志）**：`docker ps` 里 api 的 Up 时间 << nginx 的 Up 时间，且 `docker logs llmops-nginx` 报
> `connect() failed (111: Connection refused) upstream "http://<旧IP>:5001/..."`，而 `docker inspect llmops-api` 的 IP 不是那个 ⇒ 就是它。
> 一条命令修：`docker restart llmops-nginx`。

## 二、为什么必须动 Celery

`llmops-celery` 与 `llmops-api` **共用同一个镜像 `llmops-api:0.1.0`**，文档解析后的向量化任务在 Celery 里跑。只重启 api 会出现「页面上能对话，但上传文档后一直是解析中/向量化用旧凭证」这种半生效状态。

## 三、迁移

`alembic upgrade head` 在 api 容器启动脚本里执行（项目硬约束：只有 api 容器跑迁移）。本次新增迁移 `b7d21e9c4a55`（`add_platform_setting`，`down_revision='a1f4c8b2d9e3'`），启动日志确认执行成功：


建表结果已核实：`TABLE: platform_setting`。
