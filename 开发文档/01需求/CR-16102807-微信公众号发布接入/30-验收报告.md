## 三、排查中发现并修掉的 3 个问题（重点看这个）

### 1. 原项目 openid 取错 —— 会导致**所有用户串号**

```python
# 原项目（错）
openid = msg.target   # → 公众号自己的 gh_xxx id
# 实测 wechatpy：source = FromUserName(用户) / target = ToUserName(公众号)
openid = msg.source   # 已修正
```

**如果不修**：所有微信用户共用一条 `wechat_end_user`，一个人能看到另一个人的对话历史。

### 2. 子线程静默失败 —— 端口只看到「处理中」永不结束

原项目 `_thread_chat` 没有 try/except，线程内异常只打到进程 stderr（本项目 logging 配置下还没落盘），接口早已返回「思考中」，用户就卡在那儿。

**修复**：统一兜住异常 + 把 `message.status` 写为 `error`，用户回复「1」时能看到具体原因。

### 3. 根因：tiktoken 联网下载，国内卡几分钟

`faulthandler` dump 线程栈定位到：

```
ssl.read ← requests.get ← tiktoken.load.read_file ← get_encoding("cl100k_base")
                                                       ↑ model_entity.get_num_tokens_from_messages
```

BPE 文件默认缓存在 `/tmp`，容器一重启就丢。**已把编码文件预置进镜像**，实测从「分钟级」→ **0.195 秒**。

> 这条不只修微信：**普通聊天的 token 统计走同一函数**，同样受益。

## 五、已知边界（重要）

1. **必须公网可达**。当前 `SERVICE_API_PREFIX=http://localhost/api`，微信服务器访问不到。**这是能否用起来的唯一门槛**，不是代码问题。
2. **AC-07 未点过界面**（只确认产物打包 + 接口全通）。
3. **未做真实微信联调**：微信的重试机制（5 秒超时重发 3 次）、素材消息、关注/取关事件都未验证。
4. **AppSecret 明文存库**（D-04）。
5. **同一 openid 并发提问**可能产生多条会话（原项目「先查后建」非原子）。

## 六、要真正用起来，还差三步（都在你手上）

1. **准备公网地址**：公网 IP + 80/443 映射到本服务，或上内网穿透（如 frp / ngrok）。
2. **改 `docker/.env`**：
   ```bash
   SERVICE_IP=你的公网IP
   SERVICE_API_PREFIX=http://你的公网IP/api
   ```
   然后 `docker compose up -d llmops-api && docker compose restart llmops-nginx`。
3. **公众号后台**（已认证的订阅号/服务号）→「设置与开发 → 基本配置 → 服务器配置」：
   - URL 填页面上的「服务器地址(URL)」
   - Token 填页面上配置的那个 Token
   - 消息加解密方式选**明文模式**
   - 点提交，微信会请求我们的 GET 接口验签 —— 通了就保存成功

完成后在公众号里发任意消息即可，回复「1」拿结果。
