# 阶段路由与测试策略（细则）

> 本文件是 `SKILL.md` §2 的**展开**：每个阶段的判据、测试策略三档的准入条件与四条硬约束、
> 部署请求为什么不是例外。
> 常驻只记「哪条路走哪些阶段 + 三档叫什么」；**要判断某个阶段该不该跑、或要改测试策略时，读这里**。

## 2. 三阶段路由

阶段是否执行由「项目状态 + 需求性质」决定，不要求用户记命令。判断依据写在每个阶段条款里。

### 🟢 CONSTRUCTION（怎么做）

逐单元循环，一个单元的设计与代码做完再进下一个：

| 阶段 | 何时执行 | 规则文件 |
|---|---|---|
| 功能设计 | 新数据模型、复杂业务规则 | `construction/functional-design.md` |
| NFR 需求 | 有性能/安全/扩展性/技术栈选型 | `construction/nfr-requirements.md` |
| NFR 设计 | 上一步执行了 | `construction/nfr-design.md` |
| 基础设施设计 | 涉及部署架构、云资源 | `construction/infrastructure-design.md` |
| 代码生成 | 每个单元总是执行（先计划→批准→生成） | `construction/code-generation.md` |

全部单元完成后：**构建与测试** → `construction/build-and-test.md`。
**按 `团队配置.md` 的「测试策略」执行，默认 `仅静态`**（见下）。

#### 测试策略（三档，写在 `团队配置.md`）

| 档位 | 做什么 | 不做什么 | 准入条件（**三条全满足**才可降到该档） |
|---|---|---|---|
| `全量` | 新增用例 + 跑全量回归 + 人工走查清单 | — | 默认建议档：有持久化数据 / 有数据迁移 / 会多轮迭代 |
| `仅回归` | **不新增**用例，但必须跑**既有全部**用例 | 不设计新测试 | 不碰数据模型、不碰渲染层结构 |
| `仅静态` | **语法校验**（读代码 + 语言服务/编辑器报错）+ **人工测试** | **不执行任何脚本命令**：`npm/pnpm/yarn run *`、`test`、`build`、`lint`、`dev`、`tsc`、`vite` 一律不跑；也不写用例 | 默认档；用户可随时改成 `全量` 或 `仅回归` |

**`仅静态` 的两个连带约束**

- **`团队配置.md` 的「构建命令」必须留空**：`hooks/_summary.sh` 读到非空命令就会在合并后执行，
  留一行 `pnpm build` 等于在这个档位下偷偷跑了构建。要构建就同时把档位升到 `全量` / `仅回归`。
- **不许写「构建通过 / 测试通过」**：没跑就是没跑；只能写「语法校验通过（未执行命令）+ 人工测试结论」。

**四条硬约束（任何档位都成立）**

1. **档位由用户在 `团队配置.md` 定，agent 不得按改动类型自行升档**。
   `仅静态` 就是**绝对不跑**——即使本次是持久化数据、数据迁移、存储层替换，**也不破例、不提示升档、不再询问**
   （2026-10-21 用户明确要求：「绝对不跑，别问」）。
2. **降档必须留痕**：`验收报告.md` 写明「本轮策略＝仅静态，未做自动化测试」，以及**因此未覆盖的风险**。
   测试可以省，「我知道这里没验证」不能省。
3. **静态检查不能宣称「测试通过」**：语法过了不等于行为对。报告里只能写「语法校验通过（未执行命令）」。
4. **档位标签必须与实际动作一致**：新增了用例就记 `全量`；只跑了既有的记 `仅回归`；
   一旦实际动作超出所标档位，改标并说明——**写「仅回归」却新增用例属于记录失真**。

> **代价（用户已知悉并选择接受）**：数据类改动在 `仅静态` 下**没有任何自动化保护**。历史参照：R6 的
> localStorage → IndexedDB 迁移是靠 74 条用例才发现字段级问题；同类改动在 `仅静态` 下只能靠人工验收。

### 🟡 OPERATIONS

占位阶段（`operations/operations.md`），当前只做说明，不产出实际运维动作。

> **⚠️ 部署 / 上线不是例外，也不是「顺手做一下」**
>
> 「占位阶段」指的是**本流程不定义运维阶段的做法**，**不是**「部署请求可以不进流程」。
> 用户说「部署到线上」「发个链接给同事」「发布一下」时，它仍然是一次**变更请求**，必须：
>
> 1. 登记 CR（哪怕只有一句话）；
> 2. 补需求增量：部署目标、访问方式、数据影响（如 localStorage 按 origin 隔离，换域名会不会丢数据）、回滚办法；
> 3. 按项目当前审批模式过门禁（`全自动`也要留痕，`仅需求审批`至少过 G1）；
> 4. 写审计。
>
> **禁止**：跳过以上直接生成 `.deploy/` 脚本或 `dist/` 产物。
>
> 历史事故（2026-10-18，CodeBuddy）：用户只发「部署到线上，能发个链接给同事」，AI 直接产出
> `.deploy/start-lan.ps1` 与 `dist/index.html`，**审计、CR、门禁三样全无**，事后要靠翻 git 才知道做过什么。
