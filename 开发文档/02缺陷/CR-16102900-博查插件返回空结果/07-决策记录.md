# 07-决策记录

## 2026-10-29 21:10 · 修「参数名」而不是给博查写特判

- **背景**：现象是「调用成功但零结果」，直连实测显示 `count=1` 时博查稳定返回空数组。
- **选项**：
  A. 在 `tool_func` 里识别博查域名，把 `count=1` 改成 10；
  B. 修正插件参数名（`count` 重复 → 第二个改为 `page`），让模型看到正确的参数语义；
  C. 只改工具描述，提示模型「count 是条数」。
- **决定**：B（+ A/C 不做）。
- **理由**：`count=1` 是**参数语义错位**的下游结果，不是上游 bug；改参数名后模型自然会传 `count=10`、`page=1`，
  且对**所有**导入的插件普遍生效（重名校验）。
- **被否**：A 把上游怪癖硬编码进平台，换插件即失效；C 改描述治不了重名覆盖，模型仍只看到一个 `count`。

## 2026-10-29 21:10 · 可选参数补 `default=None`

- **背景**：`required: false` 的参数只写 `Optional[T]`，pydantic v2 里没有 default 仍算必填，JSON Schema 的 `required` 会包含它。
- **决定**：`Field(default=None, description=...)`，仅当 `required=True` 时用 `Field(...)`。
- **理由**：让 JSON Schema 与插件定义一致，模型不必为可选参数编造值（`freshness=oneDay` 就是这么来的）。
- **被否**：不改 —— 会继续让模型对每个可选参数填一个"看起来合理"的值，本次事故的直接诱因之一。

## 2026-10-29 21:10 · 空结果给「平台提示」而不伪造内容

- **背景**：`webPages.value: []` 时模型只能自己判断「接口成功但没内容」，容易答成「我拿不到数据」而不给建议。
- **决定**：工具返回值末尾追加一行 `[平台提示] 接口调用成功但结果列表为空（0 条）…`，正文保留上游原文。
- **理由**：平台比模型更清楚"这是空结果而不是解析失败"，且必须禁止模型编造。
- **被否**：直接返回「没有结果」四个字 —— 丢失上游原始 JSON，排障时无法区分"真没结果"和"解析错"。
