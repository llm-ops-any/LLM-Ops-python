# CR-16102802 决策记录

## 2026-10-28T-- · 归 `03技术债` 而非 `01需求`

- **背景**：PO 只说「合并开发文档」，没说要不要保留两套
- **选项**：`01需求`（用户可感知的新行为）/ `02缺陷`（与已批准预期不符）/ `03技术债`（只有开发者能感知）
- **决定**：`03技术债`
- **理由**：系统跑起来的样子一个像素都没变；动机是「文档别维护两份」，纯开发者可维护性
- **被否**：`02缺陷` —— 并存是既成事实，不是「本来该这样却没做到」

## 2026-10-28T-- · 两条既有 CR **不重编号**

- **背景**：合并后同一类型目录下会出现跨子项目的 CR；理论上可以按根项目重排
- **选项**：重编为 `CR-16102803`/`04` / 保留原号 `16102700`、`16102702`
- **决定**：保留原号
- **理由**：① 号里含「人编号 + 日期 + 当日序号」，重编等于伪造时间线；② 已有跨文档引用（`CR-16102700/状态.md` 指向根 `CR-16102701`，`CR-16102701` 侧也提过 `16102700`），重编会断链；③ 号段由「人 1 / 10-27」算得，两条本来就不撞
- **被否**：重编 —— 收益只是「看起来整齐」，代价是审计链断裂

## 2026-10-28T-- · 子项目规则并入根 `00规则/` 同一份文件，不另建子目录

- **背景**：ui-to-code 是另一套技术栈（TS / Next.js），规则与根（Python / Vue）不同
- **选项**：① 根 `00规则/` 下建 `ui-to-code/` 子目录放四份规则；② 并进同四份文件，用「第 11 节 / 第十章 / 子项目差异段」隔离；③ 保留 `ui-to-code/开发文档/00规则/` 不动
- **决定**：②
- **理由**：`文档结构.md` 规定「三步判定，没有第四步」，`00规则/` 只答「规则/共识」；再开一层子目录等于第四步，且下一个人要先知道该读哪一层。并进同一份文件时，**差异点集中在一节**，找得到也读得完
- **被否**：① 多一层路由，等于把「两套文档」缩小成「两套规则」；③ 与 PO「统一维护根目录」直接冲突

## 2026-10-28T-- · `ui-to-code/开发文档/` **整目录删除**，只留桩锚点

- **背景**：删了以后从 `ui-to-code/` 进入的 agent 没有入口
- **选项**：① 整目录删、`AGENTS.md`/`CLAUDE.md` 改写指向根；② 留 `ui-to-code/开发文档/` 空目录 + 一个说明文件；③ 整目录删，锚点也删
- **决定**：①
- **理由**：② 会被下一次「初始化」当成已存在的项目再次填满，等于复活第二套；③ 会让 `ui-to-code/` 变成无锚点的裸目录，agent 进来不读任何规则
- **被否**：②③
