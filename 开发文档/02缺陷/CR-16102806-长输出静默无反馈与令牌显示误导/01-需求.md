# CR-16102806 需求（缺陷修复的预期行为）

- **类型**：缺陷（与已批准预期不符，**不停 G1**）
- **来源**：PO 2026-10-28 18:17 截图反馈（原话见 `02-问题.md` §1）
- **关联**：`CR-16102804-内置PPT生成工具`（pptx provider 已交付，非本 CR 范围）

## 一、预期行为（本 CR 要达成的目标）

### FR-01 静默期必须可见
流式响应期间，若连续 **≥20 秒**没有收到任何内容块，界面必须给出明确的进行中提示（含已等待秒数），而不是维持一个毫无变化的转圈。
一旦恢复输出或流结束，提示立即消失。

### FR-02 Token 未就绪时不得显示 0
流式进行中或统计尚未下发时，Token 区不得显示 `0 Tokens`，应显示无歧义的状态（如「统计中」/「—」）。
流结束且统计就绪后，显示真实数值。

### FR-03 静默超时必须能终止
后端对「连续无内容块」的静默设置**独立于总超时**的上限（默认 300 秒）。超过后必须向前端下发明确的错误事件并结束流，不允许继续干等。
正常的长输出（实测最长静默约 105 秒）不得被误杀。

### FR-04 三处聊天界面行为一致
`首页辅助 Agent`（`HomeView.vue`）、`应用调试`（`PreviewDebugChat.vue`）、`WebApp 发布页`（`IndexView.vue`）三处的静默提示与 Token 显示规则必须一致。

## 二、不做（明确排除）

| # | 不做什么 | 原因 |
|---|---|---|
| 1 | 缩短上游 105 秒静默本身 | 属 uino 中转平台 / `deepseek-v4-flash` 的生成行为，我方无控制权 |
| 2 | 降低 `listen_timeout` 总超时 | 600 秒是长任务的兜底，贸然降低会误伤；改为新增「静默超时」维度 |
| 3 | 改 nginx 超时 | 后端会先于 nginx 给出错误事件，外层无需变更 |
| 4 | 给应用自动挂载 pptx 工具 | 属应用配置，PO 已自行验证通过 |
| 5 | 流式期间实时估算 Token | 需要换取增量 usage，网关不提供，且估算值与最终值必然不一致，反而误导 |

## 三、验收标准

| AC | 内容 | 判定方法 |
|---|---|---|
| **AC-01** | 静默 ≥20 秒时出现「已等待 N 秒」提示，恢复输出后消失 | 人为卡住上游（断网/压测桩）观察界面 |
| **AC-02** | 正常短问答（<20 秒）不出现任何额外提示，不打扰用户 | 常规提问走查 |
| **AC-03** | 流式期间 Token 区不出现 `0 Tokens`；结束后显示真实数值 | 观察 + 查库核对 |
| **AC-04** | 静默超过 300 秒时，后端下发错误事件，前端退出 loading 并显示原因 | 把阈值临时调小（如 10s）触发验证 |
| **AC-05** | 三处界面行为一致（AC-01~03 在三个视图各验一次） | 逐视图走查 |
| **AC-06** | 不影响既有 SSE 事件契约，`agent_end` 正常收尾 | `curl -N` 全链路复测 + 回归 `CR-16102803` 语音接口 |
