## 1. 用户原话（一字不改）

> 先把2-3做了，pptx作为按照原项目代码方式做成内置工具

> 还有那些不同看一下

（"2-3" 指上一轮差异清单里的一-2「pptx 内置工具」与二-3「`api/Dockerfile` 补 `HF_ENDPOINT`」；后者见 `CR-16102805`。）

## 2. 背景

课程原项目 `imooc-llmops` 有内置工具 `pptx`（`markdown_to_pptx`）：把 Markdown 文本用 `mistune` 渲染成 slide，交给 `python-pptx` 生成 `.pptx`，再上传 COS 返回下载链接。
本项目未移植，导致插件广场只有 google / time / duckduckgo / dalle / gaode / wikipedia / web_search 七个 provider。

> 曾评估「走 `docs/PPT自动生成工具/` 的 API 插件路线」，PO 现明确要求**按原项目代码方式做成内置工具**，故走本 CR。

## 3. 目标

1. 插件广场出现「PPT工具包」，可在应用编排里勾选。
2. 传入一段 Markdown，能生成真实 `.pptx` 并返回可下载 URL。
3. 与既有工具同一套注册机制（YAML），不写死、不改动其它 provider。

## 4. 范围

### 4.1 做

- 移植 `providers/pptx/`：`__init__.py`、`markdown_to_pptx.py`、`markdown_to_pptx.yaml`、`positions.yaml`、`_asset/icon.png`。
- 在 `providers.yaml` 注册 `pptx`（分类 `tool`）。
- 依赖：`mistune`、`python-pptx`（连带 `pillow`、`xlsxwriter`）——同时写 `requirements.in` 与 `requirements.txt`。

### 4.2 不做

| 不做 | 理由 |
|---|---|
| 改 `python-pptx` 的版式/主题 | 原项目就是 `slide_layouts[5]`（Title Only）简单排版，保持一致才能对照课程 |
| 支持图片下载到 COS 之外的存储 | `PPTRenderer` 里有 `urllib` 下载图片的逻辑，沿用 |
| 前端改动 | 插件广场与编排都是按 provider 动态渲染，注册即出现 |
| 生成任务异步化 | 原始实现同步生成（秒级），PP 文档通常不长，暂不引入 celery |
| 新增 pptx 相关测试用例 | 项目测试策略为 `后端端到端`，本 CR 用真实生成验证 |

## 5. 功能需求

### FR-01 工具注册

- `providers.yaml` 增加 `pptx` 条目（`label=PPT工具包`、`category=tool`），`positions.yaml` 列出 `markdown_to_pptx`。
- **AC-01** `GET /api/builtin-tools` 返回里存在 `pptx` provider 且含 `markdown_to_pptx` 工具。
- **AC-02** `GET /api/builtin-tools/pptx/icon` 返回 200 且为图片。

### FR-02 生成能力

- `markdown_to_pptx(markdown=...)` 返回 COS 下载地址（或本地 URL，取决于 COS 是否配置）。
- **AC-03** 传入一份含标题/多级标题/列表/表格的 Markdown，返回 URL 且 `HTTP 200`、`Content-Type` 为 pptx。
- **AC-04** 异常输入（空 markdown）不抛 500，返回「生成PPT演示文稿失败」类提示。

### FR-03 依赖

- 四个包按原项目版本锁定：`mistune==3.1.2`、`python-pptx==1.0.2`、`pillow==11.1.0`、`xlsxwriter==3.2.2`。

## 6. 验收前置

- COS 已配置（`CR-16102600` 之后已实测可传），否则工具会走本地 `storage/uploads/` 兜底（本项目 `cos_service` 已有该分支）。
- 无需新增凭证。
