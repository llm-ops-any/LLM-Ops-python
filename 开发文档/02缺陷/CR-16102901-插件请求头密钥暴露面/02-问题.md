# 02 问题（诊断结论）

- 诊断时间：2026-10-29 21:30 ~ 21:42
- 提问：插件 header 里配置的 key 有被暴露的风险吗？
- 结论：**有。3 处接口明文回显 + 前端明文回填 + 数据库明文裸存。**

## 一、暴露面清单（逐个定性）

| # | 位置 | 谁能访问 | 泄漏什么 | 严重度 |
|---|---|---|---|---|
| 1 | `api_tool_schema.py:136,148` → `GET /api-tools` 列表 | 已登录账号 | **本账号全部插件的 headers 明文**，`page_size=100` 一次拉全量 | 严重 |
| 2 | `api_tool_schema.py:89,99` → `GET /api-tools/<id>` 详情 | 已登录账号（归属校验通过） | 单个插件 headers 明文 + `openapi_schema` 原文 | 高 |
| 3 | `api_tool_schema.py:125` → `GET /api-tools/<id>/tools/<name>` | 同上 | 工具详情里嵌 `provider.headers` 明文 | 高 |
| 4 | `ui/src/views/space/tools/ListView.vue:118,461-463` | 浏览器 / 录屏 / DevTools | 编辑弹窗 `form.headers = provider.headers` 明文回填，`<a-input>` 无 `type=password` 无掩码 | 中 |
| 5 | `ui/src/hooks/use-tool.ts:24,43,95` | DevTools / 内存 | 三个 `ref` 常驻明文 headers | 中 |
| 6 | `model/api_tool.py:40` | DBA / 备份 / 只读副本 / SQL 注入 | `headers = Column(JSONB)` 明文落库，**未接入 `lib/secret.py` 的 Fernet** | 中-高 |

| 运行时请求日志（`api_provider_manager.py`） | 无任何 logging/print |

## 二、越权（他人插件密钥）

**当前不可利用**：三条读接口都做了 `account_id` 校验

```python
# api_tool_service.py:106  列表 SQL 层过滤
filters = [ApiToolProvider.account_id == account.id]
# :135  详情归属校验
if api_tool_provider is None or api_tool_provider.account_id != account.id:
    raise NotFoundException("该工具提供者不存在")
```

**但有两处防御缺口**（不是现在的洞，是将来容易变成洞）：

1. `app_config_service.py:264-267` 校验工具存在时**没带** `account_id` 过滤 → 可把他人的 provider
   name/icon/description 回显到自己的配置里（仅元信息，不含 headers）。
2. `api_tool_service.py:119-122` 先按 `provider_id+name` 查出来、再在 Python 里比对 `account_id`，
   过滤条件应该前移到 SQL。

`api/model/api_tool.py:79-82` 的 `ApiTool.provider` 是无鉴权关系访问，靠调用方自觉，属设计债。

## 三、为什么说是"遗漏"而不是"设计选择"

同一个仓库里，模型供应商这条线已经做全了：

```python
# model_provider_service.py:151-152  写入即加密
if api_key:
    cipher_text = encrypt_secret(api_key.strip())

# model_provider_schema.py:13-19  响应只给掩码
"""大模型服务设置响应结构，不含任何密钥明文"""
has_api_key = fields.Boolean(dump_default=False)
masked_api_key = fields.String(dump_default="")
```

而 api_tool 这条线 `encrypt_secret` 一次都没调用。`lib/secret.py` 现成可用。

## 四、真实风险排序（不夸大）

1. **多人共用账号**时，任何登录者点开"工具"页就能看到全部 `sk-` —— 本机目前有 2 个账号
   （`admin@llmops.com`、`758922096@qq.com`），如果只自己用，这条风险等同于"自己看自己的"。
2. **截屏 / 录屏 / 远程协助 / DevTools 截图** —— 编辑弹窗直接把 key 显示在输入框里，一次协作分享就漏。
3. **`pg_dump` 备份、数据库只读副本、CDC 同步** —— 明文 `sk-` 随备份出去。
4. 反向代理 / APM 若记录响应体，`GET /api-tools` 的响应里就带着 key。

## 五、修复落点（供选档位）

| 档 | 内容 | 改动面 | 影响 |
|---|---|---|---|
| **A** | 响应脱敏：`api_tool_schema.py` 四处改成只回 `key` + `masked_value`（或 `has_value`）；前端输入框掩码，编辑时"不修改则保留原值" | 1 个 schema + 1 个 vue + 1 个 types | 接口契约变更，需同步 `api/docs/01.项目API文档.md` 与 `ui/src/models/api-tool.ts` |
