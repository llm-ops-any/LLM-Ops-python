# 06-执行计划

## 目标 / 非目标

- 目标：博查插件在 `Agent聊天助手` 里能返回真实结果；同类「参数重名」插件在**导入时**就报错；工具执行失败/空结果对模型有明确反馈。
- 非目标：不改博查插件以外的业务逻辑；不重构 `_tools_node`；不动发布配置（`app_config` 三行历史快照保持不动）。

## 改动清单（文件级）

| # | 文件 / 对象 | 改什么 |
|---|---|---|
| 1 | `api/internal/core/tools/api_tools/entities/openapi_schema.py` | parameters 循环里加**同接口内参数重名检测**，命中即 `ValidateErrorException` |
| 2 | `api/internal/core/tools/api_tools/providers/api_provider_manager.py` | `tool_func` 加 `timeout=30`、非 2xx 显式报错、空 body / 空结果列表加平台提示；`_create_model_from_parameters` 给可选参数 `default=None` |
| 3 | `api/internal/core/agent/agents/function_call_agent.py` | `_tools_node` 的 `except` 补 `logging.exception`（失败可查） |
| 4 | `docs/虚拟数字人-批量生成口播视频、直播推流/1-3 API插件.json` | 第 5 个参数 `count` → `page` |
| 5 | 数据库 `api_tool_provider.openapi_schema`、`api_tool.parameters` | 存量记录第二个 `count` → `page`（两处同步） |

## 执行步骤

1. 改 `openapi_schema.py`：重名即拒绝（`parameter.name` 在**同一 operation 内**必须唯一）。
2. 改 `api_provider_manager.py`：请求健壮性 + 可选参数默认值。
3. 改 `function_call_agent.py`：异常落日志。
4. 修正样例 JSON。
5. 重建 `llmops-api` 镜像 → `docker compose up -d api` → **重启 nginx**（记忆：只连容器内 api 会漏 502）。
6. 修正数据库存量记录，并用 API 复核插件详情返回的 parameters。
7. 验证：8 条后端清单 + 本 CR 专项（见下）。

## 验收映射

| AC | 验证方式 |
|---|---|
| AC-01 插件详情里参数名唯一（`count` + `page`） | 调 `GET /api/tools/<provider_id>` 看 `parameters` |
| AC-02 导入重名参数插件被拒 | 造一份双 `count` 的 schema 走导入接口，应返回明确错误 |
| AC-03 对话里问天气能拿到真实搜索结果 | 应用调试接口发「北京今天天气」，看 `message_agent_thought.observation` 中 `webPages.value` 非空 |
| AC-04 上游 4xx/5xx 时模型看到明确失败原因 | 临时指向不可达 URL 的工具（构造一次调用）或直接单测函数 |
| AC-05 空结果时返回内容带平台提示 | 用 `count=1` 的等价请求触发，检查返回值末尾有提示语 |
| AC-06 工具超时不挂死 | 代码层确认 `timeout` 存在 + 单次调用实测耗时有上界 |

## 风险与回退

- 导入期加严校验 ⇒ 已存在重名参数的插件**后续编辑保存会报错**，这是期望行为；回退方式：容忍重名则改回。
- 数据修正只改 `name` 字段，不动 key、不改鉴权头；回退 SQL 见 `07-决策记录.md`。
- 空结果提示语会进入模型上下文，可能被复述。提示语用「[平台提示]」前缀区分，正文仍保留上游原文。

## 不做什么

- 不给博查写专用适配（`count=1` 的怪癖属上游行为，靠"参数名正确"规避，不硬编码特殊情况）。
- 不清理 `app_config` 的三行历史快照、不改 `publish` 语义。
