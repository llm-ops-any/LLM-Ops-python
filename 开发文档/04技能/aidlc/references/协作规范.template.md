# 协作规范

> **整份复制**到 `开发文档/00规则/协作规范.md` 再改。只写**本项目要执行**的差异，通用道理不抄。
> 完整规则在 `04技能/aidlc/references/common/parallel-collaboration.md`；**本文件与它冲突时以本文件为准**（项目更严）。
> 单人作业：**第 1 节和第 5 节必留**（取号不花时间，撞号要重编一整条线），第 2~4 节可删，并在 `文档结构.md` 写明「暂不建」。
> 多人并行：全留，人编号表在 `团队配置.md` 里填，本文件引用它，不重复列人。

## 一、取号：目录名就是号，开工先占号

**铁律：唯一标识一律用 `CR-<8位号>`，当天序号 `N` 只用于排序。**

号的计算：`P` + `Y` + `MMDD` + `N`

| 位 | 含义 | 取值 |
|---|---|---|
| `P` | 人编号（一人一位，分配后不改） | 见 `团队配置.md` |
| `Y` | 年份末位 | 2026 → `6` |
| `MMDD` | 月日 | 10 月 29 日 → `1029` |
| `N` | 当日第几个（`00`~`99`，从 00 起） | 当天已有 1 个 → `01` |

**取号三步（第一步不能跳）**

1. `git pull` —— 看到所有人（含你自己别的机器）已占的号；
2. 数 `<类型目录>/CR-<P><Y><MMDD>*/` 已有几个（**只看类型目录那层**），取下一个 `N`；
3. 建 `开发文档/<类型目录>/CR-<8位号>-<简称>/`，至少写一份 `00-状态.md`
   （`创建` 写占号这一刻，`更新` 每改一次状态刷一次），然后 `commit` + **`push`**。
   被拒是正常的：`pull` → 重算 `N` → 再推。

**禁止**：往 `00-状态.md` 里写「占号记录」（共享单文件，并发写必冲突）；
用「日期-名字」之类的命名代替 CR 号做标识。

## 二、分支：一人一分支，过门禁才合

```bash
git switch -c iter/CR-<8位号>-<短名>
# …开发…
git switch main && git pull --rebase
git switch iter/CR-<8位号>-<短名> && git rebase main   # 每天至少一次
# 过了 G3（或本项目档位对应的最后一道门）
git switch main && git merge --no-ff iter/CR-<8位号>-<短名>
```

- **禁止**直接往 `main` 推；**禁止**两人同一分支。
- 分支名用 CR 号，不带人名 —— 人已经在号里了。
- 单人、且只碰互不相交目录时，可以在 `main` 上小步提交，但**必须先 push 占号**。

## 三、目录边界：并行写不到一起

| 内容 | 谁能写 |
|---|---|
| `00规则/*` | 只有 PO；其他人发现问题在会话里提，不直接改 |
| `<类型目录>/CR-<你的号>/*` | 该 CR 的负责人独占 |
| `_汇总/*` | **谁都不手写**，由 `汇总.py` 生成 |
| 交付物类目录（`public/`、`dist` 源、资源包等） | 视为交付物变更，必须先有 CR，且同一时间只允许一条 CR 在改 |

**共享文件只允许「追加一行」，不允许「改同一行的内容」。**

## 四、撞号 / 冲突怎么办

**先合不改号，后合改号**：已进 `main` 的不动，后合的整条线重编。

| 项 | 后合者怎么改 |
|---|---|
| `CR-<号>` 目录 | 整目录改名成新号，全文替换引用 |
| `FR-48~59` | 整体平移到 `FR-57~68`（按最大号 +1 起） |
| `AC / NFR` | 同号段平移 |
| `00-状态.md` / `40-审计-*.md` | 里面的号同步改，**别只改标题** |

自查（应为空）：`grep -o 'FR-[0-9]*' 01-需求.md | sort | uniq -d`

合并冲突按顺序处理：列冲突文件 → 数冲突块 → 文档类两边都留（后到者重编号）→
代码类按语义合并 → 跑构建命令 → 在 `40-审计-<人>.md` 写一条「合并 / 编号冲突解决」。

## 五、开工前自检

- [ ] CR 目录已建（含 `00-状态.md`）、已 commit、**已 push**
- [ ] 在自己分支上，不在 `main`
- [ ] 今天做过 `git rebase main`
- [ ] 本轮要改的文件，是否有人这轮也在改（看对方 `06-执行计划.md` 的改动清单）
- [ ] 会同时改同一文件时：先约定谁先合，后者负责重编号
