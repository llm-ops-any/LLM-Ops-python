# 04-风险

## 修复前的风险（已定性）

| 风险 | 触发条件 | 影响 | 等级 |
|---|---|---|---|
| 接口明文回显 | 任何登录态访问 `GET /api-tools` | 拿到本账号全部插件密钥 | 高 |
| 页面明文回填 | 编辑插件、截屏/录屏/共享屏幕 | 密钥随截图外流 | 中高 |
| 数据库明文 | `pg_dump` 备份、只读副本、CDC、SQL 注入 | 密钥随数据外流且难追溯 | 中高 |
| 日志/SSE 泄漏 | —— | 已核查，**不存在** | 无 |
| 越权读他人密钥 | 换 `provider_id` | 被 `account_id` 校验挡住 | 低 |
| WebApp / 发布配置泄漏 | 分享链接 | 发布配置不含 headers | 无 |

## 修复后的风险（本次引入或残留）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 主密钥变更导致全部密钥解不开 | 与模型供应商密钥同一套 Fernet，同一风险面 | 解密失败降级为空值 + warning 日志，不炸应用；重填即可 |
| 前端未重建时提交 `****` | 旧前端把掩码当值提交 | 后端把 `****` 识别为「不修改」，行为正确 |
| 无法通过接口清空某个请求头的值 | 空值被解释为「沿用原密钥」 | 要清空请删除该请求头；空鉴权头本身无意义 |
| 用户忘记已有密钥，以为输入框里的 `****` 就是真值 | 认知问题 | 表格上方已加说明文案 |
| 代码回退后密文无法被旧代码使用 | 旧代码不做解密 | 回退必须同时回退数据，脚本见 `07-决策记录.md` |

## 未覆盖 / 需另立 CR

1. **密钥轮换**：本次只做静态加密，没有定期轮换、没有 KMS/外置密钥管理。
2. **`openapi_schema` 字段**：它原样回传给前端（插件详情接口），若用户导入的 schema 里自带
   `Authorization` 之类的 header，仍可能被回显。本次未处理——需要产品决定"导入的 schema 是否允许携带 header"。
3. **审计日志**：没有记录"谁在什么时候读过插件配置"，无法事后追溯异常读取。
