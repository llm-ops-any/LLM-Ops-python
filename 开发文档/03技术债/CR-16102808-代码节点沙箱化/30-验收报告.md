## 一、修好了什么

**改之前**：`code_node.py` 用一行 `exec(code, {}, local_vars)` 在 API 进程里直接跑用户代码。任何能编辑工作流的人（或拿到 API 凭证的人）等于拥有：

- 执行任意命令（`os.system`）
- 读 `/app/api/.env` → 数据库密码、JWT 密钥、各平台 API Key
- `while True` 占死 worker、`[0]*10**8` 吃光内存

**改之后**：

| 能力 | 现状 |
|---|---|
| 崩溃 / 死循环 / 内存炸弹 | ✅ 只影响子进程，API 不受影响；5 秒被杀 |
| 读环境变量 | ✅ 子进程只剩 `PATH/LANG/PYTHONIOENCODING/PYTHONDONTWRITEBYTECODE` |
| `import os/subprocess/socket/urllib.request` | ✅ 拒绝，并给可读原因 |
| `open()` / `eval` / `exec` / `getattr` | ✅ 拒绝 |
| 写文件 | ✅ 拒绝（AST + `RLIMIT_FSIZE=0` 双保险） |
| 现有工作流 | ✅ 输出逐字段一致 |

## 三、我替你决定的（请过目）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **用子进程，不挂 docker.sock 起容器** | 挂 socket 等于把宿主机 root 交给 API 容器，**比不隔离更危险** |
| 2 | **模块白名单**而非黑名单 | 黑名单永远漏；白名单漏了加一行就行 |
| 3 | 禁 `sys` 和 `getattr` | 这俩是绕过限制的经典跳板（`sys.modules['os']`、`getattr(__builtins__,'eval')`） |
| 4 | 环境变量**清空式**传递 | compose 注入了 30+ 变量，逐条拉黑以后新增就漏 |
| 5 | 超时 5 秒 / 内存 512MB / 禁写文件 | 代码节点是数据加工，正常毫秒级；5 秒能覆盖大数据量 |
| 6 | **保留**原有 6 类校验提示原文 | 用户见过这些文案，改了会误判成"改坏了" |

## 四、已知残留（必须知道）

**本 CR 不能彻底防住「读文件系统」。**

如果攻击者绕过 AST 检查（理论上可行），仍可能 `open('/app/api/.env')` 读到密钥。
本 CR 的定位是：把「**一行 exec 就能 RCE + 读光所有密钥**」降到「**需要专门绕过 + 拿不到环境变量 + 搞不垮服务**」。

彻底解决需要 mount namespace / seccomp / 独立沙箱服务，**当前 Docker-in-Docker 架构做不到**。
如果将来要多租户开放，应单独立项做「独立沙箱服务」。

其他残留：

| # | 残留 | 影响 |
|---|---|---|
| 1 | fork 炸弹未实测 | root 不受 NPROC 限制，靠 `killpg` 兜底 |
| 2 | `RLIMIT_FSIZE=0` 测不到实际效果 | `open` 在 AST 层就被拦，够不到它 |
| 3 | 白名单外模块不可用（如 numpy/pandas） | 用户需报「不允许导入」，加白名单即可 |
| 4 | 每次 14ms 起进程开销 | 相对工作流整体可忽略 |
