# CR-16102808 变更说明

## 一、项目级事实变化

| 维度 | 变化 |
|---|---|
| 安全模型 | 工作流 code 节点从「进程内 exec」改为「独立子进程 + 资源上限 + 受限 builtins」 |
| 依赖 | **无新增**（全部标准库） |
| 数据库 | 无 |
| 接口 | **无变更**（错误仍走 `FailException`，成功仍返回 dict） |
| 前端 | 无变更 |
| 运行开销 | 每次代码节点 +约 14ms（起 Python 子进程） |

## 二、行为变化（用户可见）

| 场景 | 改造前 | 改造后 |
|---|---|---|
| 纯计算 / json / hashlib / base64 | 正常 | **正常**（白名单内） |
| `import os` 等危险模块 | 可以执行 | **拒绝**，提示「代码中不允许导入模块 os」 |
| `open()` / `eval` / `exec` | 可以执行 | **拒绝**，提示「不允许调用 xxx」 |
| 死循环 | 卡死 worker | 5 秒终止，提示「超出资源限制」 |
| 超大内存 | 可能拖垮容器 | 512MB 上限 |
| 读写环境变量 | 全部可见 | 只剩 4 个基础变量 |

> 也就是说：**正常的代码节点用法一字未变，危险用法被明确拒绝并给出原因**。
