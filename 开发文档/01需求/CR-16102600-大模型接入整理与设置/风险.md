# 风险

> 格式：可能性 / 影响 / 触发信号 / 应对。**交付前逐条回看**。

## R1 删除供应商后旧应用调用失败
- **可能性**：高（库里/工作流里可能存着 `openai`+`gpt-4o-mini` 的旧配置）
- **影响**：应用打开即失败，用户看到「之前能用现在不能」
- **触发信号**：`load_language_model()` 抛 `ValueError: 模型供应商不存在`
- **应对**：FR-02 在**读取阶段**回退到 `uino`+`deepseek-v4-flash`，并打告警日志；不改库、可逆
- **残余风险**：开放 API 的调用方若在请求体里显式传 `provider=openai`，需同样回退（不能只改应用配置路径）

## R2 上下文/输出上限是推定值
- **可能性**：确定（平台 `/v1/models` 不返回规格）
- **影响**：前端显示的上下文长度可能偏大；若某模型实际更小，长对话会被平台拒绝
- **触发信号**：长对话报 `context_length_exceeded` 之类 400
- **应对**：统一保守值 + YAML 注释标注「推定」；遇到报错按实测改单条 YAML

## R3 主密钥变更导致密文解不开
- **可能性**：中（换 `JWT_SECRET_KEY` 时）
- **影响**：解密异常，若未捕获会导致所有模型调用 500
- **触发信号**：解密抛 `InvalidToken`
- **应对**：解密失败一律降级为「未配置」→ 回退 env → 设置页提示「密钥已失效，请重新填写」；**不抛穿**

## R4 多进程缓存导致「改了没生效」
- **可能性**：中（gunicorn 4 worker + Celery 独立进程）
- **影响**：页面显示已保存，部分请求仍用旧 key，表现为「时好时坏」——最难排查的一类
- **触发信号**：同一请求多次刷新结果不一致
- **应对**：不缓存整份配置对象；用**短 TTL（≤10 秒）**读库 + 保存时清本进程缓存；把「≤10 秒生效」写进 AC-13 实测

## R5 加密库用法踩坑
- **可能性**：低-中（`Fernet` 要求 32 字节 urlsafe base64 key）
- **影响**：启动即报错，或加密结果不稳定
- **应对**：主密钥派生用固定算法（`sha256(JWT_SECRET_KEY + 固定盐)` → `urlsafe_b64encode`），写在一个 `api/pkg/` 小模块里，不散落

## R6 慢模型被误判为不可用
- **可能性**：中（`gpt-5.6-sol` 首测 120s 超时）
- **影响**：验收时误删可用模型
- **触发信号**：单次超时、重测通过
- **应对**：判定标准写死为「≥2 次重试均失败才算不可用」；测试连接超时阈值设 ≥ 15s 并明确提示「超时不等于凭证错误」

## R7 改完没重建镜像
- **可能性**：高（本项目最经典的坑）
- **影响**：代码与模型 YAML 都是烘焙进镜像的，改文件不生效，白查半天
- **应对**：`docker compose build llmops-api` → `up -d` → **`restart llmops-nginx`**（否则全站 502）；写进 `构建说明.md`

## R8 前端重建遗漏
- **可能性**：中（设置页改的是 `ui/`）
- **影响**：后端接口已在，页面看不到入口
- **应对**：`docker compose build llmops-ui` 并写进构建说明

## R9 key 通过日志或异常栈泄漏
- **可能性**：中（`requests` / `httpx` 异常常带完整 URL，某些库会带 header）
- **影响**：`docker compose logs` 里出现明文 key，属于安全事件
- **应对**：所有对外请求包 try/except 且**不打印 headers 与完整异常对象**；测试连接失败只回 `status + 原因`；交付前 `grep` 一次日志

## R10 星号「不可复制」实现过度或不足
- **可能性**：中
- **影响**：过度（`user-select:none` 导致整页不能复制）或不足（选中仍能复制 `****`，其实无害但用户要求了）
- **应对**：只对 `****` 那一段加 `user-select: none`，不影响同页其它文本；不引入剪贴板拦截逻辑

## R11 切换向量化模型后，库里既有向量与新模型不同空间（**交付时已存在，需后续处理**）
- **可能性**：高（本 CR 已把默认模型改为 `text-embedding-v4`）
- **影响**：知识库（Weaviate `Dataset` 集合）里在旧模型下写入的片段向量，与新模型的查询向量不在同一空间，表现为「检索结果不相关」而不报错——最难发现的一类
- **触发信号**：知识库命中率突然变差、检索内容与问题无关
- **应对**：①预置 FAISS 索引已实测与 v4 同空间，辅助 Agent 不受影响；②**用户自建知识库的片段需重新向量化**（删片段重建 / 重跑索引任务），这属于跨 CR 的数据迁移，本次不做，已在验收报告列为后续事项
- **残余风险**：若不做数据迁移，历史知识库检索质量下降但没有报错

## R12 中转平台的 embeddings 接口不接受 tiktoken 分词数组
- **可能性**：确定（不设 `check_embedding_ctx_length=False` 时必现 400）
- **影响**：知识库片段新增/检索全线 400，早期被误诊为「阿里 text-embedding 与 langchain 不兼容」，从而错把模型换成不可用的 `qwen3-embedding-8b`（503）
- **触发信号**：`contents is neither str nor list of str`
- **应对**：代码里固定 `check_embedding_ctx_length=False` 并加注释，`.env` 注释写明原因，避免下次再被误判成模型问题
