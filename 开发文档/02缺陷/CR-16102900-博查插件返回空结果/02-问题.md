# 02-问题 · 博查插件调用返回空结果

## 1. 现象（PO 原话）

> 调用了博查AI插件，但是没有返回内容
> http://localhost/space/apps/537ff1f2-f44f-4ede-9b9f-512a76e0e1f0

- 应用：`Agent聊天助手`（`537ff1f2-f44f-4ede-9b9f-512a76e0e1f0`），模型 `uino / deepseek-v4-pro`
- 用户问「北京今天天气」，前端能看到工具调用卡片，但模型回答「搜索返回空结果，拿不到数据」
- 期望：搜到内容并按结果作答；实际：接口 HTTP 200、结果列表为空

## 2. 取证

### 2.1 数据库：工具确实被绑定了、确实被调用了

草稿配置（调试链路走的是它，不是 `app_config`）：

```sql
select config_type, version, tools from app_config_version
where app_id='537ff1f2-f44f-4ede-9b9f-512a76e0e1f0';
-- draft  v0  [{"type":"api_tool","params":{},"tool_id":"WebSearchAPI",
--               "provider_id":"f2d15dc1-0326-4a49-a624-d31052cc7f6a"}]
-- published v1/v2/v3  []
```

> 附带事实：`app_config` 表同 app 有 3 行、`tools` 全空 —— 那是 2026-10-17 的三次发布快照，
> 运行时（调试）读的是 `app.draft_app_config_id` → `app_config_version(draft)`，**不是** `app_config`。
> 这不是本缺陷的原因，但排障时容易看错表。

`message_agent_thought` 最近三次调用（2026-10-29 13:00~13:01）：

| 时间 | tool | tool_input | observation |
|---|---|---|---|
| 13:00:37 | `<uuid>_WebSearchAPI` | `{"count":1,"query":"北京天气预报 今天 最新","summary":true,"freshness":"oneDay"}` | `code:200`，`webPages.value: []` |
| 13:01:42 | 同上 | `{"count":1,"query":"北京今天天气 实时天气 温度 空气质量",...}` | 同上，`value: []` |
| 13:01:47 | 同上 | `{"count":1,"query":"北京天气 今天 实时",...}` | 同上，`value: []`，`someResultsRemoved: true` |

三次都成功发出、上游都返回 200，**只有 `count` 恒为 1**。

### 2.2 插件定义里 `count` 出现了两次

`api_tool.parameters`（原文）：

| # | name | in | description |
|---|---|---|---|
| 1 | query | request_body | 用户的搜索词 |
| 2 | freshness | request_body | 搜索指定时间范围… |
| 3 | summary | request_body | 是否显示文本摘要 |
| 4 | **count** | request_body | 返回结果的条数…范围 1-50，默认 10 |
| 5 | **count** | request_body | **页码，默认值为 1** |

第 5 个参数名应为 `page`（博查官方参数名），源文件 `docs/虚拟数字人-批量生成口播视频、直播推流/1-3 API插件.json` 里同样写错。

### 2.3 直连博查分组实测（同一 key、同一 query）

query = `北京天气 今天 实时`：

| count | summary | freshness | 返回条数 |
|---|---|---|---|
| 1 | true | oneDay | **0** |
| 1 | false | noLimit | **0** |
| 1 | true | noLimit | **0** |
| 10 | false | oneDay | 9 |
| 10 | true | noLimit | 9 |
| 10 | false | noLimit | 9 |
| 不传 | — | — | 9 |

结论：**`count=1` 时博查稳定返回 `webPages.value: []`**（总命中量仍在 12 万量级，结果被过滤掉）。
`freshness` / `summary` 均无关，账号额度正常（10 条能正常返回）。

## 3. 根因

```
插件 JSON 第 5 个参数名写错（count 应为 page）
  → openapi_schema.py 只校验 name 是字符串，不查重
  → api_tool.parameters 落库后含两个 count
  → api_provider_manager._create_model_from_parameters 里 fields[name] 字典赋值，后者覆盖前者
  → 模型拿到的唯一 count 字段描述是「页码，默认值为 1」
  → 模型按"页码"理解，传出 count=1（想取第 1 页）
  → 博查把 1 当"返回条数"，只取 1 条又全部被过滤 → webPages.value = []
  → tool_func 把原始 JSON 原样返回，不判断空结果
  → 模型只能说「接口成功但没有内容」
```

放大因素（同批修掉）：

1. `_create_model_from_parameters` 对 `required: false` 的参数只写 `Optional[T]`，**没给 default** ——
   pydantic 里仍是必填，模型被迫给每个可选参数编一个值（这正是 `count=1`、`freshness=oneDay` 的来源）。
2. `tool_func` 无 `timeout`、无 `raise_for_status`、不看空结果，HTTP 500 / 空 body / 空列表全都"成功"返回。
3. `function_call_agent._tools_node` 的 `except Exception` 只把异常变成一句字符串，不写日志。

## 4. 影响

- 该应用**所有**走博查插件的提问都拿不到结果，且模型与用户都得不到「为什么空」的线索。
- 同类风险不限于本插件：任何导入时参数重名的插件都会静默丢参数；任何工具请求超时都会把整个 Agent 请求挂住。
