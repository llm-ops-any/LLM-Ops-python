## 2. 背景

课程原项目有 `audio` 模块（`/audio/audio-to-text`、`/audio/message-to-audio`），本项目**未迁移**。
差距比对见 `证据/原项目差距比对.md`。前置实测结论（详见 `前置资源.md`）否掉了「照抄原项目」这条路：

- 本项目唯一的大模型通道（中转平台 `token.uino.com/v1`）**没有任何语音能力** —— TTS 8 个候选模型全 503；ASR `fun-asr` 挂名不可调。
  ⇒ 原项目的 `whisper-1` + `tts-1` 实现**无法复用**。
- 阿里百炼侧可用，且 PO 已验证 `qwen3.8-omni-flash-realtime`。

## 3. 目标

1. **浏览器优先**：默认配置就用浏览器能力（ASR 用 Web Speech API，TTS 用 `SpeechSynthesis`），零成本、零网络、不出后端。
2. **一条配置项切换三档**：`browser` / `omni` / `dashscope`，改完即生效，便于 PO 对比三种效果。
3. **TTS 按需启动**：不点播放不建连接、不产生计费；配置为 `browser` 时后端零调用。
4. **接口与前端契约稳定**：沿用 `/audio/message-to-audio` 的 SSE 事件名（`tts_message` / `tts_end`），换引擎不改契约。

## 4. 范围

### 4.1 做

- 新增平台级配置项「语音服务」（`platform_setting` 表 `name=speech_provider`）：引擎、各引擎模型名与音色、阿里百炼 API Key（加密存储、掩码回显）。
- 后端新增 `internal/core/audio/` provider 包：`browser`（返回前端执行约定）/ `omni`（WebSocket→SSE）/ `dashscope`（CosyVoice TTS + Paraformer ASR）。
- 后端新增接口：语音配置读写、`/audio/audio-to-text`、`/audio/message-to-audio`。
- 前端新增「语音服务」设置区、消息朗读按钮、按引擎切换的录音实现、应用编排两个能力开关。
- 回写 `api/docs/01.项目API文档.md`。

### 4.2 不做（明确排除）

| 不做 | 理由 |

## 5. 功能需求

### FR-01 语音服务配置项

平台设置弹窗新增「语音服务」，可读写以下项（落 `platform_setting`，`name=speech_provider`）：

| 字段 | 说明 |
|---|---|
| `engine` | `browser`（默认）/ `omni` / `dashscope` |
| `dashscope_api_key` | 阿里百炼 Key；**加密存储、仅回显掩码**，为空表示不修改 |
| `omni_model` | 默认 `qwen3.8-omni-flash-realtime` |
| `omni_voice` | 默认 `Aiden` |
| `omni_host` | Realtime 的 WebSocket 主机（业务空间专属域名，不同于通用域名） |
| `cosyvoice_model` | 默认 `cosyvoice-v3-flash`（**不是** `v3.5-flash`，见 `前置资源.md` P-04） |
| `cosyvoice_voice` | 默认 `longxiaochun_v3` |
| `paraformer_model` | 默认 `paraformer-realtime-v2` |

- **AC-01** `GET /api/speech-provider` 返回当前配置；响应全文**不含** `sk-`，`masked_api_key` 固定 `****`。
- **AC-02** `POST /api/speech-provider` 切换 `engine` 后，**10 秒内**再 `GET` 读到新值（沿用大模型设置的缓存口径）。

### FR-02 浏览器档（默认）

- ASR：沿用 `ChatInputBar.vue` 现有 Web Speech API 实现，不改行为。
- TTS：`window.speechSynthesis` 朗读消息文本，**不请求后端**。
- **AC-03** `engine=browser` 时，点朗读按钮**不产生** `/audio/message-to-audio` 请求（浏览器网络面板确认为 0 条）。

### FR-03 Omni 档（qwen3.8-omni-flash-realtime）

- 服务端用 `websocket-client` 连 `wss://{omni_host}/api-ws/v1/realtime?model=...`，`Bearer` 鉴权。
- 会话配置：`modalities=["text","audio"]`、`turn_detection=null`、`instructions` 强约束「逐字朗读、不回应、不改写」、输出 `pcm/24000`。
- 流程：`session.update` → 等 `session.updated` → `conversation.item.create`(input_text) → `response.create` → 收 `response.audio.delta` 逐块转 SSE。
- **AC-04** `POST /api/audio/message-to-audio` 对一条 10 字以上中文消息，返回 SSE 且**至少 1 个** `tts_message` 事件携带 base64 音频，末尾有 `tts_end`；音频可按 24k/16bit/单声道 播放且内容与原文一致。

### FR-04 DashScope 档（CosyVoice + Paraformer）

- TTS：`dashscope.audio.tts_v2.SpeechSynthesizer`，模型与音色取配置。
- ASR：`dashscope.audio.asr.Recognition`（流式回调），模型取配置。
- **AC-05** `POST /api/audio/audio-to-text` 上传一段含中文语音的 16k wav，返回非空文本。
- **AC-06** TTS 该档同样走 `/audio/message-to-audio`，SSE 契约与 AC-04 一致。

### FR-05 降级与错误可读

- 未配置 Key 或引擎不可用时，接口返回**明确业务提示**（如「语音服务未配置，请在设置中填写阿里百炼 API Key」），**不得 5xx**。
- `engine=browser` 时后端两个语音接口被调用，返回「当前引擎由浏览器执行」的提示，不报错。
- **AC-07** 清空 Key 后调用 TTS → HTTP 200、`code≠success` 且 message 含「未配置」；`docker logs` 无 `Traceback`。

### FR-06 应用级开关

- 应用编排新增「语音转文本」「文本转语音」两个能力项，落既有 `app_config_version.speech_to_text / text_to_speech`（字段与校验**已存在**，无需迁移）。
- 关闭时对应按钮不出现在调试页 / 首页 / WebApp。
- **AC-08** 打开「文本转语音」并保存 → 刷新后仍为开启；关闭后消息上不再有朗读按钮。
