## 2. 数据流

```
[浏览器] 选文件
   │  File
   ▼
POST /api/upload-files/attachment      ← 登录态（access_token），非开放 API
   │  返回 ChatAttachment {name, extension, size, mime, kind, text?|url?, truncated?, note?}
   ▼
values.files = [ChatAttachment, ...]   ← 表单值（与 api_key/app_id 同级）
   │
   ├─► buildRequest()  ──► body.files（非空时才有该字段）
   │        └─► POST /openapi/chat  （只带 API Key，credentials:'omit'）
   │
   └─► buildCurl()     ──► 右侧「等价请求」里的 --data-raw

[后端 /openapi/chat]
   OpenAPIChatReq.files ──ChatAttachmentsMixin 校验──► 合法附件列表
        │
        ├─► build_query_with_attachments(query, files) ──► HumanMessage（单条≤8000/总≤20000字符）
        └─► build_attachment_metadata(files) ────────────► Message.attachments（text 截 4000）
```

## 3. `files` 契约（对外）

```json
{
  "app_id": "…",
  "query": "这份报告的核心结论是什么？",
  "stream": true,
  "files": [
    { "name": "报告.pdf", "extension": "pdf", "size": 48213, "mime": "application/pdf",
      "kind": "text", "text": "…解析出的正文…", "truncated": false },
    { "name": "架构图.png", "extension": "png", "size": 92311, "mime": "image/png",
      "kind": "image", "url": "https://…cos…/xxx.png", "note": "图片未解析文本，已上传对象存储" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 文件名（不能为空） |
| `kind` | 否 | `text` / `image` / `file`，仅影响上下文里的中文标签，缺省按 `text` 处理 |
| `text` | 二选一 | 正文；≤100000 字符（超限 400） |
| `url` | 二选一 | 可访问地址；与 `text` 至少一个非空 |
| `extension`/`size`/`mime`/`truncated`/`note` | 否 | 透传展示用，不参与校验 |

- 上限：**≤5 个**；单文件 ≤30MB（上传阶段拦）；注入上下文单条 ≤8000、总 ≤20000 字符（`helper.py` 既有）
- **不传 `files` 时请求与改造前完全一致**（`buildRequest` 跳过空数组，后端 `default=[]`）

## 4. 前端设计

### 4.1 元数据（`endpoints.ts`）

```ts
type EndpointField.type = 'string' | 'boolean' | 'enum' | 'files'

// chat 端点 fields 中，紧跟 query 之后插入：
{ name: 'files', label: '附件', in: 'body', type: 'files', required: false,
  tip: '可选。图片交给视觉模型识别，文档会自动解析成文本一起提问；最多 5 个、单个不超过 30MB' }

// 与后端 upload_file_entity.py 对齐（D2：同一组数字，不另定义）
export const ATTACHMENT_LIMIT = { count: 5, size: 30 * 1024 * 1024 }
```

`sample` 不写 `files`（文档示例保持无附件形态，`files` 由 §3 的示例承担）。

### 4.2 `buildRequest` 空数组处理

```ts
const isEmpty = value === undefined || value === null || value === ''
  || (Array.isArray(value) && value.length === 0)
```
> 只有这一处改动。注意**不能**把 `[]` 当合法 body 发出去 —— 会破坏 AC-05 的「字段不出现」。

### 4.3 `buildCurl` 折叠

新增 option `collapseAttachments?: boolean`：为 `true` 时对 body 内每个 `files[i].text` 做展示截断
（保留前 200 字符 + `…（共 N 字符，完整内容见复制/请求体）`），`JSON.stringify` 前用深拷贝，**不改原 body**。

- `curlText`（遮蔽 key）→ `collapseAttachments: true`
- `curlFullText`（完整 key，用于复制）→ `collapseAttachments: false`

> D6：展示可以缩水，复制必须可执行。

### 4.4 `AttachmentInput.vue`

| 项 | 设计 |
|---|---|
| props | `modelValue: ChatAttachment[]`、`limit: { count: number; size: number }`、`disabled?: boolean` |
| emits | `update:modelValue` |
| 交互 | 「添加附件」按钮 + 隐藏 `<input type="file" multiple>`；选中后**先本地校验**（数量、单文件大小），通过才逐个调 `uploadFileText` |
| 状态 | `uploading: { uid, name, size }[]`（loading chip）、`errorText: string`（一次性提示，3s 消失） |
| 并发 | 逐个串行上传（`for...of await`），避免同时打 5 个解析任务把后端 CPU 打满 |
| chip | 图标按 `kind` 区分（text=文档 / image=图片 / file=文件）＋ 文件名 ＋ 大小 ＋ 关闭按钮（`data-testid="attachment-remove"`） |
| 发送后 | **chip 保留**（Q4 的「回显」落地，见 `风险.md` R-05），用户手动删 |
| 失败 | `Message.error(中文原因)` + chip 不入列表；该文件可从错误提示重试 |

关键：`modelValue` 里只放**上传成功**的 `ChatAttachment`，上传中的条目单独放 `uploading`，两者渲染到同一个 chip 列表，保证顺序稳定。

### 4.5 `RequestForm.vue`

`v-for` 内新增最前分支：

```vue
<AttachmentInput
  v-if="field.type === 'files'"
  :model-value="values[field.name] ?? []"
  :limit="ATTACHMENT_LIMIT"
  :disabled="loading"
  @update:model-value="(files) => updateField(field.name, files)"
/>
```
位置天然在「用户提问」下方（fields 数组顺序）。

### 4.6 `PlaygroundView.vue`

1. 表单初值：`field.type === 'files' ? [] : field.defaultValue ?? (field.type === 'boolean' ? false : '')`
2. `expandAttachments = ref(false)` → 传给 `buildCurl` 的 `collapseAttachments: !expandAttachments`，经 `v-model:expand-attachments` 与 `ResponsePanel` 双向绑定
3. 页头 `<p>` 追加：附件由平台上传解析（走你的登录态），**对话请求仍只带下方 API Key**；第三方调用需自备 `text` 或可公开访问的 `url`

### 4.7 `ResponsePanel.vue`

「等价请求」工具条新增 `a-checkbox v-model="expandAttachments"`（文案「展开附件内容」），默认**不勾**（折叠）。
复制按钮始终用 `curlFull`，与折叠开关无关。

### 5.2 service（`chat()`）

```python
# 8.新建消息记录（落附件元信息）
message = self.create(Message, **{
    ..., "query": req.query.data,

# 15.智能体状态

    "messages": [HumanMessage(build_query_with_attachments(req.query.data, req.files.data))],  # ← 包装
```

## 6. 兼容性与风险落地

| 关注点 | 结论 |
|---|---|
| 老客户端不传 `files` | `default=[]` → `build_attachment_metadata([]) == []`、`build_query_with_attachments(q, []) == q`，行为零变化 |
| 请求体体积 | 5 × 100000 字符上限 ≈ 500KB，nginx 40M 无压力；真实场景受上传端 20000 字符解析上限约束 |
| R-01 curl 卡顿 | 折叠为 200 字符占位（§4.3），复制仍全文 |
| R-04 鉴权误解 | §4.6 页头文案 + §9.6 API 文档写明（无上传端点） |
| 落库体积 | `text_limit=4000` 既有默认，不改 |
