## 一、为什么需要它

当前实现（本 CR 已交付）把代码执行从 API 进程挪到了**独立子进程**，防住了：崩溃、死循环、内存炸弹、环境变量泄露、常见危险调用。

**但防不住一件事**：绕过 AST 检查后，子进程**仍在同一个容器内**，理论上可以 `open('/app/api/.env')` 读到数据库密码等。
彻底解决需要**换隔离边界** —— 让代码跑在另一个容器里，那里根本没有那些文件。

## 二、架构

```text
┌──────────────┐   HTTP (internal 网络)   ┌───────────────────┐
│ llmops-api   │ ───────────────────────> │ llmops-sandbox    │
│ 有 DB 凭证   │   POST /run {code,params}│ 只读、无外网、非 root │
└──────────────┘                          └───────────────────┘
```

**关键技巧**：`networks.sandbox_net.internal: true`
→ 该网络没有默认网关，容器之间能互通、但**访问不了互联网**。
这样「沙箱要收 api 的请求」和「沙箱不能上网」可以同时成立，不需要额外 iptables 规则。

## 三、施工清单

### 3.1 新增沙箱服务

`api/sandbox/app.py`：

```python
from flask import Flask, request, jsonify
from runner import _run          # 直接复用 sandbox_runner 里的执行体

app = Flask(__name__)

@app.post("/run")
def run():
    try:
        payload = request.get_json(force=True)
        return jsonify({"ok": True, "result": _run(payload)})
    except MemoryError:
        return jsonify({"ok": False, "error": "内存超限"})
    except Exception as e:
        return jsonify({"ok": False, "error": f"{type(e).__name__}: {e}"})
```

`api/sandbox/Dockerfile`（约 15 行）：

```dockerfile
FROM python:3.10-slim
WORKDIR /sandbox
RUN pip install --no-cache-dir flask==3.1.0
COPY sandbox/runner.py  ./runner.py
COPY sandbox/app.py     ./app.py
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
USER 1000:1000
EXPOSE 8000
CMD ["python", "-m", "flask", "--app", "app", "run", "--host", "0.0.0.0", "--port", "8000"]
```

> `runner.py` = 把现有 `sandbox_runner.py` 改造成可 import（暴露 `_run`，去掉 `__main__` 里的 stdin/stdout 逻辑）。

### 3.2 compose 配置

```yaml
services:
  llmops-api:
    networks: [default, sandbox_net]      # 加一条

  llmops-sandbox:
    image: llmops-sandbox:0.1.0
    build:
      context: ../api
      dockerfile: sandbox/Dockerfile
    container_name: llmops-sandbox
    restart: always
    read_only: true
    tmpfs:
      - /tmp:size=16m,noexec,nosuid
    cap_drop: [ALL]
    security_opt:
      - no-new-privileges:true
    pids_limit: 64
    mem_limit: 256m
    cpus: 0.5
    user: "1000:1000"
    networks: [sandbox_net]
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request;urllib.request.urlopen('http://127.0.0.1:8000/health')"]
      interval: 30s
      timeout: 3s
      retries: 3

networks:
  sandbox_net:
    internal: true
```

### 3.3 code_node 改造

只替换执行段，**AST 校验、常量、错误文案全部保留**：

```python
import requests

resp = requests.post(
    "http://llmops-sandbox:8000/run",
    json={"code": code, "params": params},
    timeout=SANDBOX_TIMEOUT + 1,
)
data = resp.json()
if not data.get("ok"):
    ...  # 沿用现有错误映射
return data["result"]
```

**要点**：连不上沙箱时**直接报错，不要降级回本地 exec** —— 否则沙箱名存实亡。

## 四、落地前必须确认（写错不报错但不生效）

| # | 确认项 | 怎么查 |
|---|---|---|
| 1 | `pids_limit` / `mem_limit` / `cpus` 在**当前 compose 版本**是否按顶层字段生效 | `docker compose version`，然后 `docker inspect llmops-sandbox \| grep -E "PidsLimit\|Memory\|NanoCpus"` —— 看到实际值才算生效 |
| 2 | 非 root（uid 1000）下 Flask 能否正常启（/tmp 可写、无 `__pycache__`） | 起容器后看日志 |
| 3 | `read_only` 下 Python 是否还需要别的可写路径 | 同上 |
| 4 | `internal: true` 网络里 api 能否解析 `llmops-sandbox` 主机名 | 在 api 容器内 `python -c "import socket;print(socket.gethostbyname('llmops-sandbox'))"` |
| 5 | 沙箱容器**确实访问不了外网** | 容器内 `python -c "import urllib.request;urllib.request.urlopen('https://baidu.com',timeout=3)"` 应超时/失败 |

> ⚠️ 第 1 条最容易踩：compose 的 `deploy.resources.limits` 在非 Swarm 模式下**部分字段会被忽略**，必须用 `docker inspect` 回读实际生效值，不能只看 yaml 写了。

## 五、验收要点

| AC | 内容 |
|---|---|
| AC-S1 | 现有快递鸟工作流输出与改造前一致 |
| AC-S2 | 沙箱容器内**无法**访问外网（超时） |
| AC-S3 | 沙箱容器内**读不到** `/app/api/.env`（文件不存在） |
| AC-S4 | 沙箱容器内**写不了**根文件系统（PermissionError） |
| AC-S5 | fork 炸弹被 `pids_limit` 拦住（`ps` 数量不暴涨） |
| AC-S6 | 死循环 5 秒终止，api 不受影响 |
| AC-S7 | api 连不上沙箱时报错清晰，**不降级回本地执行** |
| AC-S8 | 单次调用额外开销（多一跳内网 HTTP，预期 +2~5ms） |

## 六、更严的可选变体（暂不需要）

如果将来多租户开放，可把通信从 HTTP 换成 **unix socket**：

- 共享 volume `/run/sandbox`
- 沙箱 `network_mode: none`（彻底无网络）
- api 连 `/run/sandbox/sandbox.sock`

代价：`requests` 需加 unix transport（`requests-unixsocket` 或 httpx 自定义）。当前 `internal` 网络的隔离强度已足够，**不建议提前做**。

## 七、不做的代价

| 项 | 影响 |
|---|---|
| 绕过 AST 后仍可能读容器内文件 | 需要攻击者具备构造绕过 payload 的能力；且环境变量、数据库连接不直接暴露 |
| fork 炸弹残留 | root 不受 NPROC 限制，靠 `killpg` 兜底，极端情况下需人工清理 |

**结论**：当前风险等级对「单人或小团队自用」可接受；若开放注册使用，应优先做本方案。
