## 1. 用户原话（一字不改）

> 1、整理下agent调用大模型部分，目前平台内置的OpenAI、月之暗面、通义千问、ollama都可以去掉了，我没有这些key。只保留uino中转平台，然后可以调用的模型拉一下在线列表中的信息，丰富下可以调用的模型。
> 2、在设置页面加一个大模型设置，可以填写地址，配置大模型的key。填过的秘钥不要显示出来也不可复制，只显示****,如果需要修改就重新填

## 2. 目标

1. **平台只认一个模型来源**：删掉没有凭证的内置供应商，模型下拉只出现 uino 的模型，避免选到必然失败的项。
2. **可选模型 4 → 24**：按 uino 在线 `/v1/models` 清单逐个实测，能用的写进注册表。
3. **凭证页面可改、即时生效**：现在地址与 key 只活在 `docker/.env`，改一次要 build + recreate；改为落库、加密、即时生效。
4. **key 只进不出**：保存后只显示 `****`，不可复制、不回显、接口不返回明文。

## 5. 功能需求

### A 组：供应商精简

#### FR-01 只保留 uino
`providers.yaml` 只留 `uino`；删除 `providers/{openai,moonshot,tongyi,ollama}/`（含各 `_asset/` 图标），并删除**从未注册、实际不加载**的 `providers/wenxin/` 死目录。

- **AC-01** `GET /api/language-models` 返回长度 **1**，`name=uino`，`models` 数量 = 24。
- **AC-02** `providers/` 下只剩 `uino/` 与 `providers.yaml`。

#### FR-02 旧配置读取时回退
应用 `model_config` / `app_config_version.model_config` / 工作流 LLM 节点指向已下架 provider 或 model 时，**读取阶段**回退 `uino` + `deepseek-v4-flash`，不抛 500、不返回空白面板。

- **AC-03** 构造 `{"provider":"openai","model":"gpt-4o-mini"}` 的应用，配置面板显示 uino / deepseek-v4-flash，调试能出结果。
- **AC-04** 回退发生时后端日志有告警（含 app_id 与原 provider/model），可事后定位。

#### FR-03 清除官方模型名残留
`embeddings_service` 的 `text-embedding-3-small` 默认值、`assistant_agent_service` 注释掉的 `ChatOpenAI(model="gpt-4o-mini")`、`language_model_service` 兜底注释等，改为 uino 体系取值。

- **AC-05** `api/**/*.py`、`api/**/*.yaml`、`ui/src/**` 中 `gpt-4o`、`moonshot-v1`、`qwen-max` 作为**默认值/硬编码** 0 命中（`docs/`、`开发文档/`、`api/test/` 除外）。
- **AC-06** 代码不再读取 `DASHSCOPE_API_KEY`、`MOONSHOT_API_KEY`、`qianfan_ak/sk`（env 文件由人清理，代码不改写 env）。

### B 组：模型清单扩充

#### FR-04 按实测新增 20 个模型 YAML
在 `providers/uino/` 下每个实测通过的模型一份 `<model>.yaml`，字段与现有 4 份一致（`model`/`label`/`model_type`/`features`/`context_window`/`max_output_tokens`/`attributes`/`parameters`/`metadata.pricing`），`positions.yaml` 按「主力在前」排序。

- **AC-07** 应用模型下拉中 uino 下共 24 个模型，名称与在线清单逐字一致。
- **AC-08** 24 个模型每个至少一次真实对话（流式），其中至少 6 个完成「流式 + 工具调用」两轮。
- **AC-09** `context_window` / `max_output_tokens` 为推定值的模型，YAML 内中文注释标注「推定，平台未提供」。

#### FR-05 思考模式适配
`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-flash` 三个 YAML 必须带：

```yaml
attributes:
  extra_body:
    thinking:
      type: disabled
```

其余 21 个**不带**（实测不需要）。

- **AC-10** 上述 3 个模型各连续 3 轮「流式 + 工具调用」，0 次 `reasoning_content` 400。
- **AC-11** 不带该参数的模型任取 3 个，同样 3 轮 0 报错。

#### FR-06 能力标注
`qwen3-vl-plus`、`deepseek-v4-flash-vision-exp` 标注视觉能力（若 `features` 无视觉枚举则只写注释，不引入前端不认识的值）；其余统一 `tool_call`。

- **AC-12** 前端模型下拉对新增模型无渲染异常或空白项。

### C 组：大模型设置

#### FR-07 设置页新增「大模型设置」
在现有设置弹窗（`ui/src/views/layouts/components/SettingModal.vue`）左侧导航加第二项「大模型设置」，与「账号设置」并列。内容区：

| 字段 | 说明 |
|---|---|
| API 地址 | 完整 base_url（如 `https://token.uino.com/v1`），可编辑 |
| API Key | 已配置时只显示 `****` + 「修改」；未配置时为空输入框 |
| 当前来源 | 只读：「数据库配置」或「环境变量兜底」 |
| 测试连接 | 用当前输入值请求 `/v1/models`，返回成功或失败原因 |

- **AC-13** 保存成功后**无需重建镜像、无需重启容器**，新值 **≤ 10 秒**内对所有 worker 与 Celery 生效。
- **AC-14** 地址为空或非 http/https 时前端拦下，不发请求。
- **AC-15** 失败提示能区分：超时 / 401 未授权 / 404 路径错 / 其它。

#### FR-08 key 脱敏与不可复制
已保存的 key 任何位置不回显，只显示固定 `****`：不显示首尾位与长度；星号不可被选中复制；点「修改」进入重填态、输入框为空；**key 留空保存 = 不修改**，只改地址。

- **AC-16** 保存后刷新，key 位置仍为 `****`，`Ctrl+A` / 拖选无法选中该文本。
- **AC-17** 抓「查询设置」接口响应，`key` 字段不存在或为固定掩码，无明文无密文。
- **AC-18** 只改地址、key 留空保存后，实际调用仍能通过鉴权。

#### FR-09 加密存储
key 以密文落库（`Fernet`，主密钥由现有 `JWT_SECRET_KEY` 派生，**不新增环境变量**）。库、日志、审计记录均不得出现明文。

- **AC-19** 直接查库，key 字段为密文（非明文、非 base64 明文包装）。
- **AC-20** 后端与 Celery 日志 `grep` 不到 key 明文。
- **AC-21** 主密钥变更导致解密失败时降级为「未配置」并提示重填，**接口不 500、不崩**。

#### FR-10 生效范围覆盖对话与向量化
同时作用于：所有 chat 调用（含 4 处硬编码 `Chat(...)`：应用预设提示词生成、提示词优化、会话名/摘要/建议问题、辅助 Agent）＋ 向量化（`embeddings_service`，**1536 维不变**）。

> **施工期修正（2026-10-26，见 `变更说明.md` 第 1 条）**：需求起草时以为当前向量化模型是 `qwen3-embedding-8b`，实测该模型与 `text-embedding-3-small` 在中转平台**均无可用渠道（503）**，即知识库向量化链路本来就是断的。实际改为 `text-embedding-v4` + `dimensions=1536`（实测 200、维度 1536），并用预置 FAISS 索引做检索对比验证同向量空间。**维度不变、不改页面、不加依赖**，属缺陷修复，不改变本 FR 的验收标准。

- **AC-22** 只改设置页地址与 key（不动 `.env`），聊天与知识库检索均正常。
- **AC-23** 填错误 key 保存后，聊天与知识库**同时**报鉴权失败（证明没有分叉）。

#### FR-11 测试连接
只读接口：用**请求体传入的**地址/key 请求 `/v1/models`，返回 `{ok, status, message, model_count}`；不读不写数据库配置。

- **AC-24** 正确凭证 `ok=true` 且 `model_count=32`（当前在线数，允许随平台变动）。
- **AC-25** 错误 key 返回 `ok=false`、`status=401`、中文可读原因，响应 ≤ 15 秒。

#### FR-12 未配置时兜底与展示
库里无配置时回退 `OPENAI_API_BASE` / `OPENAI_API_KEY`；设置页「来源」显示「环境变量兜底」，地址显示 env 值，key 仍为 `****`。

- **AC-26** 清空库内配置后重启进程，平台仍可正常对话。

## 7. 实测依据（2026-10-26，直连 `https://token.uino.com/v1`）

在线清单 **32 条**，对话类 **24 条**全部通过（探测方式：`max_tokens=1` 最小请求 + 带 `tools` 的函数调用 + `stream=true` 抽样 + 工具第二轮回传）。

**需关闭思考模式的 3 个**：`deepseek-v4-flash`、`deepseek-v4-pro`、`deepseek-flash`（plain 第二轮 400，加 `thinking.type=disabled` 后通过）。
**不需要的**：其余 21 个（含 `qwen3.7-plus`、`qwen3-vl-plus`、`deepseek-v4-flash-vision-exp`、`glm-5.3`、`minimax-m3`、6 个 `gpt-5.6/6.x` 代号款）。
**参数兼容性**：24 个模型全部接受 `temperature/top_p/presence_penalty/frequency_penalty/max_tokens` 组合（`top_p=0.85`）。
**非对话类（本次不纳入）**：`qwen3-embedding-8b`、`text-embedding-v1/v3/v4`、`qwen3-rerank`、`fun-asr`、`gpt-image-2`、`qwen-image-2.0`。

**向量化模型加测（2026-10-26 施工期补测，`POST /v1/embeddings`）**：

| 模型 | 无 `dimensions` | `dimensions=1536` | 结论 |
|---|---|---|---|
| `qwen3-embedding-8b` | 503 无可用渠道 | 503 | 不可用 |
| `text-embedding-3-small` | 503 无可用渠道 | - | 不可用 |
| `text-embedding-v4` | 200 / 1024 维 | 200 / 1536 维 | **采用** |
| `text-embedding-v3` | 200 / 1024 维 | 400 维度非法 | 不可用（维度不符） |
| `text-embedding-v1` | 200 / 1536 维 | 200 / 1536 维 | 可用但检索质量不符（见下） |

同向量空间判定：拿「如何创建 LLM 应用并发布成 WebApp」在预置 FAISS 索引（260 条 / 1536 维）上做 `similarity_search_with_score`，`text-embedding-v4` 的 L2 距离约 1.88（内容为接口文档片段，相关），`text-embedding-v1` 约 10215（等于无相关性），据此判定预置索引与 v4 同空间。
**异常项**：`gpt-5.6-sol` 首测 120s 超时，重测与流式均通过 —— 属慢模型，非不可用。
