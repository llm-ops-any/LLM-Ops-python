# CR-16102807 应用设计

## 一、数据模型

```text
wechat_config（一对一 app）
  id / app_id / wechat_app_id / wechat_app_secret / wechat_token / status
  └ status: configured | unconfigured（由后端推导，前端不写）

wechat_end_user（openid ↔ 终端用户，多对一 app）
  id / openid / app_id / end_user_id
  └ 唯一性靠 (openid, app_id) 复合索引

wechat_message（待推送队列）
  id / wechat_end_user_id / message_id / is_pushed
```

`App.wechat_config` 是一个 **property 而非 relationship**：读的时候自动补建配置行、并按「三项是否齐全 + 应用是否已发布」双向修正 `status`。这样前端永远不需要手动维护状态。

## 二、请求流程

### 2.1 GET（微信保存配置时的校验）

```text
GET /wechat/<app_id>?signature&timestamp&nonce&echostr
  ├ 应用不存在/未发布 → 失败提示
  ├ 未配置 → 失败提示
  └ check_signature(token, signature, timestamp, nonce)
        ├ 通过 → 原样返回 echostr（纯文本，非 JSON）
        └ 不通过 → 失败提示
```

### 2.2 POST（用户发消息）

```text
POST /wechat/<app_id>   (XML body)
  ├ 非 text → 回「只支持文本消息」
  ├ content == "1" → 查最近一条 WechatMessage
  │     ├ 存在且未推送 → 按 message.status 回：答案 / 处理中 / 超时 / 出错
  │     └ 否则 → 当作普通提问处理
  └ 普通提问：
        ① 查/建 EndUser + WechatEndUser
        ② 复用该终端用户的 SERVICE_API 会话
        ③ 建 Message(attachments=[]) + WechatMessage(is_pushed=False)
        ④ 起子线程跑 Agent（传 flask_app 对象）
        ⑤ 立即回「思考中，请回复"1"获取结果。」
```

**关键时序约束**：③④⑤ 必须在 5 秒内完成，Agent 的全部耗时都在子线程里。

### 2.3 子线程内

```text
with flask_app.app_context():
  ├ load_language_model(app_config.model_config)
  ├ TokenBufferMemory 取最近 dialog_round 轮历史
  ├ tools = 工具配置 + 知识库检索 + 工作流
  ├ FunctionCallAgent / ReACTAgent（按 llm 是否支持 tool_call）
  ├ agent.invoke(...)
  └ conversation_service.save_agent_thoughts(...)
```

## 三、接口清单

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/platform/<app_id>/wechat-config` | 登录 | 读配置（含 url / ip） |
| POST | `/platform/<app_id>/wechat-config` | 登录 | 写配置 |
| GET | `/wechat/<app_id>` | **无**（微信验签） | 服务器校验 |
| POST | `/wechat/<app_id>` | **无**（微信消息） | 消息处理 |

> `/wechat/*` 不能加 `@login_required` —— 微信服务器不带本项目登录态。

## 四、配置项

| 变量 | 用途 | 默认 |
|---|---|---|
| `SERVICE_IP` | 展示给用户填到公众号后台的服务器 IP | 空 |
| `SERVICE_API_PREFIX` | 拼接回调 URL，如 `http://1.2.3.4/api` | `http://localhost/api` |
