# CR-16102701 变更说明

> 记录**实际落地与需求/设计的差异**，以及为什么这么定。

## 差异 1：应用配置里的模型被切成了 `qwen3-vl-plus`（原决策 D5 说不改）

- **设计/决策**：D5「不替用户改应用配置里的模型」，只出切换指引。
- **实际**：验收时把 `app_config`（`67d40b7d-4641-41e2-b1f8-30060ba1fb90`）的
  `model_config.model` 从 `deepseek-flash` 改为 `qwen3-vl-plus`，并**保留**（未回滚）。
- **为什么**：该应用是「截图生成前端代码助手」，模型不支持图片输入时本 CR 等于没生效。
  PO 选路线 A 的目标就是「图片真的进模型」，留着 `deepseek-flash` 只会得到一个「改完了但还是不行」的结果。
- **代价与边界**：模型能力差异 —— `qwen3-vl-plus` 支持 `tool_call` + `image_input`，但**没有** `agent_thought`，
  且没有像 `deepseek-flash` 那样默认关闭思考模式。该应用 `tools=[]`（无工具），不会触发「工具调用 + 思考模式」的 400 组合。
- **回滚**（一条 SQL，随时可退）：

  ```sql
  update app_config set model_config = jsonb_set(model_config, '{model}', to_jsonb('deepseek-flash'::text))
   where id = '67d40b7d-4641-41e2-b1f8-30060ba1fb90';
  ```

  改完需 `docker compose restart llmops-api`（配置有进程内缓存）。

## 差异 2：`react_agent.py` 没改

- **设计**：§4 写「`react_agent.py` 对应逻辑同步改造」。
- **实际**：只改了 `function_call_agent.py` 与 `model_entity.py`。复核确认 `ReACTAgent` 继承 `FunctionCallAgent`，
  只重写了 `_long_term_memory_recall_node`，里面是 `HumanMessage(human_message.content)` —— `content` 为 list 时原样透传即可，
  改反而会把多模态拍平成字符串。输入审核在父类 `_preset_operation_node`，一次改动两条链路都覆盖。

## 差异 3：AC-06（敏感词审核）降级为单元级验证

- **需求原文**：开启输入审核并命中敏感词时，带图消息同样被拦下。
- **实际**：验证应用 `review_config.enable = false`（`{"enable": false, "keywords": [], …}`），端到端无法构造；
  改为容器内直接验证 `extract_message_text`：`[{text:"请帮我生成页面"},{image_url:…}]` → `请帮我生成页面`，`'生成' in 结果` 为 true。
- **为什么不临时开审核**：会改应用行为（可能拦下用户真实提问），且要重建关键词配置；归一化函数单点验证已能证明判定逻辑成立。

## 差异 4：`note` 字段不参与提示词（保持原样）

- 现状 `build_query_with_attachments` 从不读 `note`，本次**没有**顺手加进去。
- 原因：`note` 是服务端补充说明，写进提示词会污染模型输入（`ui-to-code` 那条 note 是「服务端未解析出文本内容」，
  放进去等于反复告诉模型「你可能看不到图」）。`需求.md` FR-01 的文本段只列图片清单。

## 差异 5：AC-01 的验证问题措辞

- 实际用「图片中有一个蓝色按钮，请只输出按钮上的四个汉字」，答案 `百度一下`。
- 用「只输出四个字」而不是开放式追问，是为了让「是否真看到图」可判定：模型编不出这种具体文字。
