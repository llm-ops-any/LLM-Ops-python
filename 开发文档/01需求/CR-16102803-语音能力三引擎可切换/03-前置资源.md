### P-01 中转平台（本项目唯一大模型通道）：无任何语音能力

| 探测 | 结果 |
|---|---|
| `GET /models`（32 个模型） | 与语音相关仅 `fun-asr` 一项，无任何 TTS 模型 |
| `POST /audio/speech`：`tts-1`/`tts-1-hd`/`gpt-4o-mini-tts`/`cosyvoice-v1,v2`/`qwen-tts`/`qwen-audio-tts`/`sambert`/`sovits` | **8/8 全部 503 `model_not_found`**（`No available channel ... under group 标准档`） |

### P-03 `qwen3.8-omni-flash-realtime`：可用，纯文本朗读可行

实测（`qwen3.8-omni-flash-realtime`，`voice=Aiden`，`pcm/24000`，`turn_detection=null`）：

| 指标 | 值 |
|---|---|
| 连接与会话建立 | 成功（`session.created` → `session.updated`） |
| 首包延迟 | **0.51 秒** |
| 音频块数 | 12 个 `response.audio.delta` |
| 音频量 | 240640 base64 字符 ≈ 3.76 秒 PCM |
| 输出文本 | `'README 文档已更新，共三处改动。'` —— **与输入一字不差，未跑偏、未加语气词** |

**关键**：`instructions` 里写「纯朗读器，逐字朗读，不回应、不改写」后，模型不会变成对话。这条是这个档能用的前提。

#### P-03 附：朗读稳定性（2026-10-28 追加实测，**这条推翻了上面的乐观结论**）

同一句「像对话」的输入（`今天的天气很好，我们出去走走吧。`），三种约束方式各跑两轮（`api/test/manual/speech/前置实测-5-omni朗读稳定性.py`）：

| 方式 | 第 1 轮 | 第 2 轮 | 转录 |
|---|---|---|---|
| A 温和指令（初版实现） | ❌ 跑偏 | ❌ 跑偏 | `好啊，今天天气确实不错，出去走走挺舒服的。你想去哪儿？` |
| B 强指令 + 输入加`【朗读稿】`包装 | ✅ 一致 | ✅ 一致 | `今天的天气很好，我们出去走走吧。` |
| C 强指令 + `response.create` 带 instructions | ✅ 一致 | ✅ 一致 | 同上 |

**结论**：温和指令会退化成聊天，**必须用强指令**（措辞不能软化），实现里同时上 B + C 双保险。
⇒ 已改 `entity/audio_entity.py` 的 `OMNI_READING_INSTRUCTIONS` 与 `OMNI_READING_WRAPPER`（`决策记录.md` D-11）。
模型不会把`【朗读稿】`标签念出来，比对时也要先剥掉标签，否则误报不一致。

#### P-04 附：`cosyvoice-v3-flash` 真实合成闭环验证（2026-10-28，回应「控制台搜不到」）

PO 反馈「阿里百炼上搜不到 cosyvoice 相关模型，是不是给错了」，故做**闭环校验**（`api/test/manual/speech/前置实测-4-cosyvoice闭环校验.py`）：
用 CosyVoice 合成 → 落盘 → 用另一条链路 `qwen3-asr-flash` 转回 → 比对文本。

| 检查项 | 结果 |
|---|---|
| 返回字节数 | **50664 字节**（非 0、非静音占位） |
| 文件头 16 字节 | `b'ID3\x03\x00\x00\x00\x00\x00QTSSE\x00\x00'` ⇒ **真 mp3**（ID3 标签 + `QTSSE` 是通义语音的编码器标识） |
| 时长估算 | ≈ 3.17 秒（与 15 字中文正常语速一致） |
| ASR 回灌文本 | `'今天的天气很好，我们出去走走吧。'` |
| 原文 | `'今天的天气很好，我们出去走走吧。'` |
| **一致性** | **完全一致（True）** |

⇒ **模型可用、音频内容正确，不是给错。** 控制台搜不到属「可见性」问题，不影响 API 调用（见 P-06）。
补充：`VoiceEnrollmentService.list_voices()` 返回 `[]` —— 说明 `longxiaochun_v3` 是**官方预置音色**（复刻音色列表才非空），不是授权缺失。

#### P-06 控制台「搜不到 CosyVoice」的三种可能（未经 PO 环境验证，供定位）

| 可能 | 说明 | 怎么确认 |
|---|---|---|
| ① 分类不对 | 「模型广场」全局搜索按模型名命中率低，TTS 一般归在「**语音合成**」/「音频」分类下 | 在模型广场切「语音合成」分类，或直接搜 `cosyvoice-v3` |
| ② 业务空间隔离 | 该 Key 来自业务空间 `ws-...`（参考项目 `.env` 的 `API_HOST`），控制台模型广场可能只展示**该空间已部署**的模型，而 API 走公共按量付费服务 | 切到主账号默认空间再看 |
| ③ 无在线体验入口 | 官方文档里 CosyVoice 的「模型体验」标注为**不支持**，只有 API 可调 | 以能否 `SpeechSynthesizer` 调通为准（本 CR 已验通） |

**④ 官方开通路径不在百炼模型广场（2026-10-28 查证）**：CosyVoice 的原始归属是**智能语音交互（ISI）**产品线，
官方文档原文：

> "CosyVoice speech synthesis is available only in the commercial version and does not offer a free trial.
> **Activate the commercial version before using the service.**"
> —— `help.aliyun.com/isi/developer-reference/speech-synthesis/`

⇒ 若百炼侧始终找不到，去 **智能语音交互控制台 → 语音合成 → 服务状态 →「升级为商用版」**。
而百炼侧 `cosyvoice-v3-flash` 属**按量付费**（1 元/万字符，含 1 万字符免费额度），与 ISI 商用版是两条计费通道。
**本 CR 走的是百炼 SDK 通道，与 ISI 控制台无强依赖**（已实测调通）。

**⑤ 根因已定位（2026-10-28 实测）：CosyVoice 不在 OpenAI 兼容模型清单里**

`GET https://dashscope.aliyuncs.com/compatible-mode/v1/models`（用同一把 Key）：

| 项 | 结果 |
|---|---|
| HTTP | 200 |
| 模型总数 | **183** |
| 含 `cosyvoice` 的条目 | **0 条** |
| 语音相关条目 | `qwen3-tts-flash`、`qwen3-tts-flash-realtime`、`qwen3-asr-flash-realtime`、`qwen-audio-3.x-realtime`、`qwen3.5/3.8-omni-*`、`fun-asr-flash-*` |

⇒ **CosyVoice 走 DashScope 私有协议**（`/api-ws/v1/inference` + `tts_v2.SpeechSynthesizer`），
不在 OpenAI 兼容清单中，所以「模型广场 / 兼容模式列表」里搜不到它——**但 SDK 能调通（P-04 已闭环验证）**。

补充：清单里的 `qwen3-tts-flash` 在本项目 SDK（`dashscope 1.22.1`，只有 `audio/asr`、`audio/tts`、`audio/tts_v2`）
**调不通**：`MultiModalConversation` → 400；`/compatible-mode/v1/audio/speech` → 404。
要用需升级 SDK（属新增依赖，须另开技术债 CR）。**故 CosyVoice 是当前唯一可用的专用 TTS。**

> 判定口径：**以 API 实测为准**。本 CR 的两档语音能力不依赖控制台是否可见。




### P-05 Paraformer / qwen3-asr-flash：可用，但静音样本无法证明准确率

| 模型 | 用法 | 结果 |
|---|---|---|
| `paraformer-realtime-v2` | **流式回调**（`Recognition(model, format, sample_rate, callback)` + `start()` / `send_audio_frame()` / `stop()`）；`call(file=)` 会抛 `missing 'callback'` | 静音 wav → 无文本（预期），**无报错** |

⇒ 服务端 ASR 默认用 `paraformer-realtime-v2`（用户指定），但**准确率必须在验收时用真实语音复测**（见 `风险.md` R-04）。
