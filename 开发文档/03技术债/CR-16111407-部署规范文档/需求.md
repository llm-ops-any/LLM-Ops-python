## 1. 用户原话（一字不改）

> 这个项目怎么部署写到规则里吧，单独写一个md文档

## 2. 目标

1. **部署这件事在 `00规则/` 里有一份唯一权威**：怎么起、改完什么动作生效、部署后怎么验、怎么退，一个文件讲完。
2. **收掉散落的部署口径**：目前「改代码要重建镜像」「改 env 不用 build」「重建 api 后必须重启 nginx」分散在
   `团队配置.md`（例外与约定）、`docs/项目熟悉文档.md` §7/§8、共享记忆库 `项目记忆\LLMOps.md` §三；
   新人 / 新 agent 要拼三处才能拼对，且已经出现过「只 `restart` 不 `up -d`，env 不生效且不报错」的误判。
3. **只写稳定规则，不写进度与凭证**：不写「当前部署在哪台机 / 谁部署的 / 最近一次部署时间」；不出现任何密钥、密码、账号值。

## 3. 范围

### 3.1 做

- 新增 `开发文档/00规则/部署规范.md`，覆盖：
  部署形态（7 容器与端口 / 唯一对外入口）→ 前置条件 → 首次部署步骤 → **变更后生效对照表** →
  部署后验收 → 回滚与数据保护 → 子项目（`ui-to-code/` / `echoMimic/` / `gradio-demo/`）→ 硬禁区 → 坑速查。
- `开发文档/00规则/文档结构.md` 第一节布局与第四节各补登记 1 处，避免新规则文件「建了但没人知道」。

### 3.2 不做

- 不改 `docker-compose.yaml`、`Dockerfile`、nginx 配置等任何部署实现文件（**本文只是把既有事实写下来**）。
- 不改 `团队配置.md` 的 8 条后端端到端清单（那是验收判据的唯一权威，本文只引用不复制）。
- 不复制 `环境变量配置说明.md` 的配置项表（那份管「配什么」，本文管「怎么部署」）。
- 不写登录账号 / 密钥 / 密码值；不写部署进度（哪台机、何时部署、谁部署）。
- 不处理 `docs/` 历史资料的去留（只读参考，保持原样）。

## 5. 追加（2026-11-14，PO 追加，不另开 CR）

> 原话：**「项目路径不要写绝对路径，写相对路径」**

- 原因：规则文件会被换机器 / 换人阅读，绝对路径（`d:\02_Resources\...`）写死在文档里等于把本机目录结构钉进项目规则。
- 处置：`部署规范.md` 第三节、第六节、第七节全部改为相对仓库根的写法；新增 AC-10 约束全文。
- 范围不变：仍不改任何代码与容器。
