# CR-16102810 需求：WebApp 页支持朗读

- **需求性质**：增量
- **来源**：`CR-16102803` 遗留项「WebApp 页暂无朗读按钮（`web_app` 响应未带开关）」

## 一、现状

`CR-16102803` 已给 AI 消息加了朗读能力（`AiMessage` 的 `enable_tts` prop + `useAudioPlayer`），
调试页（`PreviewDebugChat`）已接入，但 **WebApp 发布页没有**：

| 位置 | 朗读按钮 |
|---|---|
| 首页辅助 Agent（`HomeView`） | ✅ |
| 应用调试（`PreviewDebugChat`） | ✅ |
| **WebApp 发布页（`IndexView`）** | ❌ **缺失** |

原因两条：
1. `/web-apps/<token>` 的 `GetWebAppResp` 只返回 `opening_statement` / `opening_questions` / `suggested_after_answer`，**没有 `text_to_speech`**；
2. `IndexView` 的 `<ai-message>` 没有传 `message_id` 和 `enable_tts`。

⇒ 应用里明明开了文字转语音，分享出去的 WebApp 页面却听不了。

## 二、功能需求

| # | 内容 |
|---|---|
| FR-01 | `GET /web-apps/<token>` 响应增加 `text_to_speech: {enable, voice, auto_play}` |
| FR-02 | WebApp 页的 AI 消息在「应用开启 TTS + 消息答案已生成完 + 有 message_id」时显示朗读按钮 |
| FR-03 | 点击后复用既有 `/audio/message-to-audio` 接口，行为与调试页一致（含 `browser` 档本地朗读） |
| FR-04 | 未开启 TTS 的应用不显示按钮，页面视觉不变 |

## 三、不做

| # | 不做什么 | 原因 |
|---|---|---|
| 1 | **自动播放**（`auto_play`） | 该字段一直只是配置项，前端从未实现；调试页也没有。本 CR 只补按钮，保持一致 |
| 2 | 页面内切换音色 | 音色是应用级配置（设置 → 语音服务），按消息单独选是另一个产品设计 |
| 3 | 改 `/audio/message-to-audio` 的鉴权 | 现有校验（登录 + 消息归属 + 应用已发布）已能覆盖 WebApp 场景，无需放宽 |
| 4 | 朗读进度条 / 字幕同步 | 超出本 CR 范围 |

## 四、验收标准

| AC | 内容 | 判定 |
|---|---|---|
| AC-01 | 开启 TTS 的应用 → WebApp 页每条已完成的 AI 消息有朗读按钮 | 界面走查 |
| AC-02 | 关闭 TTS 的应用 → 无按钮，布局不变 | 界面走查 |
| AC-03 | 点击按钮能听到声音（`browser` 档零请求，服务端档走 SSE） | 实测 |
| AC-04 | 流式输出过程中不显示按钮（避免念半截） | 观察 |
| AC-05 | 调试页 / 首页行为不变 | 回归 |

## 五、影响面

- `api/internal/schema/web_app_schema.py`（加一个字段）
- `ui/src/models/web-app.ts`（类型）
- `ui/src/views/web-apps/IndexView.vue`（传两个 prop）
- **无数据库变更、无新接口、零新增依赖**
