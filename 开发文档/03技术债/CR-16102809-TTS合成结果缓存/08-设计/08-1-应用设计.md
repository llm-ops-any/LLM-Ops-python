# CR-16102809 应用设计

## 一、缓存文件

**路径**：`storage/tts_cache/<key>.json`（key 见 §二）

**内容**：

```json
{
  "text_sha": "a1b2c3…",
  "engine": "dashscope",
  "voice": "longxiaochun_v3",
  "model": "cosyvoice-v3-flash",
  "created_at": 1761652800,
  "chunks": [
    {"audio": "<base64 PCM>", "sample_rate": 22050},
    {"audio": "<base64 PCM>", "sample_rate": 22050}
  ]
}
```

- `audio` 原样保存 provider 返回的 base64 字符串，**不做二次编解码**（避免损耗与 CPU）
- `chunks` 保持原始顺序；命中时按序回放，音频内容与首次逐字节相同

## 二、缓存 key

```python
text_sha = sha1(message.answer.strip())[:16]
voice_sha = sha1(f"{config.voice}|{config.model}")[:12]
key = f"{message.id}__{config.engine}__{voice_sha}__{text_sha}"
```

| 为什么 | 说明 |
|---|---|
| 带 `engine` | 三档引擎输出格式不同（PCM 采样率也可能变） |
| 带 `voice/model` 指纹 | 换音色必须重新合成，否则播错人声 |
| 带 `text_sha` | 消息被"重新生成"后答案变了，旧缓存自动失效 |
| 不带头像/用户 id | `message_id` 已是 UUID，不可枚举 |

## 三、改造点

只动 `audio_service.message_to_audio` 里的 `tts()` 内部生成器：

```python
def tts() -> Generator:
    common_data = {...}
    key = _cache_key(message, config)
    cached = _load_cache(key)          # 含 TTL 判断

    # 命中：直接回放，不碰 provider
    if cached is not None:
        for chunk in cached:
            yield _sse("tts_message", {**common_data, **chunk, "engine": config.engine})
        yield _sse("tts_end", {**common_data, "audio": ""})
        return

    # 未命中：边合成边收集
    collected = []
    try:
        for chunk in provider.tts_stream(message.answer.strip()):
            item = {"audio": chunk.get("audio", ""), "sample_rate": chunk.get("sample_rate", 0)}
            collected.append(item)
            yield _sse("tts_message", {**common_data, **item, "engine": config.engine})
    except CustomException as error:
        ...  # 原有错误处理，不变
        return
    except Exception as error:
        ...  # 原有兜底，不变
        return

    # 只有完整跑完才落盘（D-03）
    _save_cache(key, collected, message, config)
    yield _sse("tts_end", {**common_data, "audio": ""})
```

**关键**：`_save_cache` 在 `for` 循环正常结束后、`tts_end` 之前。异常分支直接 `return`，不会落盘。

## 四、读写实现

```python
CACHE_DIR = os.path.join(os.path.dirname(__file__), "../../storage/tts_cache")  # 实际用绝对路径
CACHE_TTL_SECONDS = 7 * 24 * 3600
CACHE_MAX_BYTES = 20 * 1024 * 1024

def _load_cache(key: str) -> list | None:
    path = CACHE_DIR / f"{key}.json"
    if not path.exists():
        return None
    if time.time() - path.stat().st_mtime > CACHE_TTL_SECONDS:
        path.unlink(missing_ok=True)       # 惰性清理（D-04）
        return None
    try:
        data = json.loads(path.read_text("utf-8"))
        return data.get("chunks") or None
    except Exception:
        path.unlink(missing_ok=True)        # 损坏文件直接删，走重新合成
        return None

def _save_cache(key, chunks, message, config) -> None:
    if not chunks:
        return
    payload = json.dumps({...}, ensure_ascii=False)
    if len(payload.encode()) > CACHE_MAX_BYTES:
        logging.info("TTS 缓存超出单文件上限，跳过写入 key=%s", key)
        return
    # 先写临时文件再 rename，避免读到半截 JSON
    tmp = path.with_suffix(".tmp")
    tmp.write_text(payload, "utf-8")
    os.replace(tmp, path)
```

- **原子写**：`tmp` + `os.replace`，防止并发读到写了一半的文件（风险 R-03）
- **目录按需创建**：`mkdir(parents=True, exist_ok=True)`

## 五、并发与中断

| 场景 | 行为 |
|---|---|
| 两个请求同时未命中 | 都去合成，都写缓存（后写覆盖）。**接受**：浪费一次调用，但不会出错（D-03 已避免半截文件） |
| 客户端中途断开 | 生成器被 GC，`for` 循环不再执行到落盘 → 不产生缓存（AC-05） |
| 缓存文件损坏 | `json.loads` 失败 → 删除 → 重新合成 |
