# 01-需求 · echoMimic 改用百炼 TTS

- 需求性质：增量

## 1. 背景

`echoMimic/webgui.py` 是本项目改造过的 EchoMimic WebUI：左侧「文案主题 → 获取文案 → 转换为语音」，
右侧数字人视频位，下方 `Configuration` 折叠区驱动 `Audio2VideoPipeline`。

其中 `text_to_speech()` 仍走上游原始实现：`openai.OpenAI` + `model="tts-1"` + `voice="alloy"`，
地址取自 `echoMimic/.env` 的 `OPENAI_API_BASE`（现为 `https://api.nekoapi.com/v1`）。
实测该中转站不提供 `tts-1`，「转换为语音」用不了；同时该实现把异常**当成字符串返回**，
而输出组件是 `gr.Audio`，字符串会被当作路径去读而崩掉整个请求。

`gradio-demo/webui.py` 在 `CR-16102902` 里已经把同一件事做对了（百炼原生 TTS + 失败弹窗 + 目录兜底），
本次把该方案搬回 `echoMimic/webgui.py`。

## 2. PO 要求（原话）

> 「把这个优化一下 @echoMimic/webgui.py，参考 @gradio-demo/webui.py 换成阿里百炼的模型」

## 3. 功能需求（FR）

| 编号 | 需求 |
|---|---|
| FR-01 | 「转换为语音」调用**阿里百炼** TTS，不再出现 `tts-1` / `alloy` / `from openai` |
| FR-02 | 接口地址、模型、音色三个参数均可由 `.env` 覆盖（`DASHSCOPE_TTS_URL` / `TTS_MODEL` / `TTS_VOICE`），缺省值取**实测可用**的组合 |
| FR-03 | 百炼返回的音频可能给下载 url，也可能给 base64，两种都要能落盘成 mp3 |
| FR-04 | 失败一律弹窗（`gr.Error`），不得把错误字符串交给 `gr.Audio` 当路径 |
| FR-05 | 文案为空时立即弹窗提示，不发无意义的付费请求 |
| FR-06 | `.env.example` 与代码实际读取的键一致；`requirements.txt` 与实际 import 一致 |
| FR-07 | 附带修复：`device` 变量算出来却没用（三处 `."cuda"` 硬编码）—— 无 GPU 机器上 import 期即崩 |

## 5. 不在本次范围

- **整站启动与数字人视频生成**：仓库无 `pretrained_weights/`（`configs/prompts/animation.yaml` 指向的 7 份权重均缺失），
  无法端到端跑通「生成视频」；本轮只验 TTS 函数与语法，视频链路按「未执行」记入 `20-测试记录.md`。
- `echoMimic/.env` 里 `LLMOPS_API_BASE=https://llmops.shortvar.com/...` 的**证书过期**问题（同 `CR-16102902` 2.2），
  修它属于服务器侧运维，本轮不动，只登记。
- `gradio-demo/.env.example` 仍写着 `qwen3-tts-flash` / `Cherry`（与实际 `.env` 不一致，且该模型当前欠费），
  属 `CR-16102902` 的遗留，本轮不顺手改，登记在 `30-验收报告.md` 建议项。
