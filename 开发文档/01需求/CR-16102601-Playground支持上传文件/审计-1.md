### 3. 现状探测（只读，未改任何文件）
- Playground 是**表单驱动的开放 API 调用器**，不是聊天 UI：用户提问 = 单行 `a-input`，无 toolbar、无附件、无 textarea。
  - 页面：`ui/src/views/openapi/playground/PlaygroundView.vue`
  - 输入区：`ui/src/views/openapi/playground/components/RequestForm.vue`（字符串字段统一渲染成 `a-input`）
  - 端点元数据（唯一认识端点的地方）：`ui/src/views/openapi/playground/endpoints.ts`，`query` 字段定义在 78–86 行
  - 请求体由 `buildRequest()` 白名单拼装：`app_id` / `query` / `stream` / `conversation_id` / `end_user_id`
- 后端开放 API 端点 `POST /openapi/chat`（`router.py:333-342` → `openapi_handler.py:25-36`）：
  - 请求 schema `api/internal/schema/openapi_schema.py` 的 `OpenAPIChatReq` **不含 `files`**
  - `api/internal/service/openapi_service.py:49` `chat()` 只把 `req.query.data` 塞进 `HumanMessage`；建 `Message` 时不写 `attachments`
- **同类接口已全部支持附件，可直接复用**：应用调试 `/apps/<id>/conversations`、辅助 Agent `/assistant-agent/chat`、WebApp `/web-apps/<token>/chat`
  - 统一校验 `api/internal/schema/chat_attachment_schema.py`（`ChatAttachmentsMixin`：数量上限、每项需 `name` + `text` 或 `url` 二者其一、text ≤ 100000 字符）
- 上传能力现成：`POST /api/upload-files/attachment`（≤30MB，返回 `name/extension/size/mime/kind/text/url/truncated`），
  前端封装 `ui/src/services/upload-file.ts` 的 `uploadFileText`，类型 `ui/src/models/upload-file.ts` 的 `ChatAttachment`。
  **注意：上传接口走登录态（`@login_required`），而 Playground 聊天请求刻意走 API Key（`credentials: 'omit'`）。**
- 消息表已有附件列：`api/internal/model/conversation.py` 的 `Message.attachments`（JSONB，默认 `[]`），
  落库/回显工具在 `api/internal/lib/helper.py`（`build_attachment_metadata` / `dump_attachment_metadata`）。
- `docs/Playground设计文档.md` 全文未提及附件。
