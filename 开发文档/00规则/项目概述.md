## 1. 一句话定位

一个**类 Dify 的「AI 应用开发平台」**：用户在网页上创建 AI 应用 → 编排提示词 / 挂工具与知识库 →
调试 → 发布成 **WebApp**（对外链接）或**开放 API**（给第三方程序调）。
平台自身另带：**工作流编排**（可视化拖拽 8 类节点）、**知识库 RAG**、**模型供应商管理**、**内置应用与插件广场**。

## 2. 交付物形态

- **网页平台**：本机自用部署，对外**只暴露 80**（nginx 唯一入口），其余端口绑 `127.0.0.1`。
- **WebApp 链接**：发布态应用可被外部访问的独立页面。
- **开放 API**：第三方按 key 调用；配套 `api/docs/01.项目API文档.md` 为接口契约，**改接口必须回写**。
- 无对外 SaaS 形态，不是库、不是桌面程序。

## 4. 运行时拓扑

编排文件 `docker/docker-compose.yaml`，全部服务在同一 Docker 网络：

| 组件 | 宿主端口 | 职责 |
|---|---|---|
| `llmops-nginx` | **80（唯一对外）** | 反代 ui 与 api |
| `llmops-ui` | `127.0.0.1:3000` | 前端（Vite 构建产物） |
| `llmops-api` | `127.0.0.1:5001` | Flask + gunicorn；**启动时负责跑 alembic 迁移** |
| `llmops-celery` | 无 | Celery worker（文档索引等异步任务） |
| `llmops-db` | `127.0.0.1:5432` | PostgreSQL 15，业务库 `llmops` |
| `llmops-redis` | `127.0.0.1:6379` | 缓存 / Celery broker / Agent 队列停止标记 |
| `llmops-weaviate` | `127.0.0.1:8080`、`50051` | 向量库 |

要点：**api 与 celery 是同一个镜像**，靠环境变量 `MODE`（`api`/`celery`）在 `docker/entrypoint.sh` 分流；
迁移只由 api 跑（`MIGRATION_ENABLED=true`，celery 为 `false`），避免重复执行。
数据全在 `docker/volumes/`（`db/data`、`redis/data`、`weaviate/`、`app/storage`）—— **清目录＝清数据**。

## 6. 核心链路

1. **应用编排 → 调试 → 发布**：`router` → `handler` → `service`（应用/会话/消息）→ `core/agent`（LangGraph）→
   模型调用（统一中转平台）＋ 工具调用 ＋ 检索；发布后由 WebApp handler / 开放 API handler 复用同一条 invoke 链路。
2. **知识库 RAG**：上传文件（落 COS / 本地 storage）→ `handler` 建 `Dataset` 记录 → **Celery 异步**切分与索引
   → 向量应用侧算好后写入 Weaviate `Dataset` collection → 检索时按 `RetrievalService` 召回注入提示词。
3. **工作流**：前端 vue-flow 拖拽生成图 → 后端 `core/workflow` 按 8 类节点（开始/结束/LLM/工具/知识库检索/代码/分支等）
   顺序执行 → 结果回写会话。
4. **鉴权**：`middleware/request_loader` 按来源分流（平台登录态 / WebApp token / 开放 API key）。

## 8. 硬约束（踩过的坑）

1. **后端代码与模型 YAML 烘焙进镜像**：改完必须 `docker compose build llmops-api` 再 `up -d`，
   `docker compose restart` 不够 —— 否则「改了没生效」，白查半天。
2. **不硬编码官方模型名**（`gpt-4o-mini` 那类）：本项目的模型全部走中转平台，官方名在平台上不存在，
   模型清单以 `api/internal/core/language_model/providers/**/*.yaml` 为准。
3. **Weaviate 向量化模块关闭**（`DEFAULT_VECTORIZER_MODULE: 'none'`）：向量必须由应用侧算好再写入，
   别指望向量库自动向量化。
4. **表结构变更只走 alembic**（`api/internal/migration/`），且只有 api 容器执行迁移；手改库会导致下轮迁移失败。
5. **`docker/volumes/` 是真实数据**，`docker compose down -v` 或清理目录 = 数据全没。
6. **密钥只放 `docker/.env`（兜底）或平台设置页（库内 Fernet 密文）**，不进仓库、不进 `开发文档/`、不进审计记录、不进日志。
7. **向量化必须 `check_embedding_ctx_length=False`**：langchain 默认先把文本 tiktoken 分词成整数数组再发送，
   中转平台只接受字符串，会报 `contents is neither str nor list of str`。早期把这个 400 误判成「阿里模型与 langchain 不兼容」，
   导致错换成不可用的 `qwen3-embedding-8b`（503）。当前正确组合：`text-embedding-v4` + `EMBEDDINGS_DIMENSIONS=1536`。
8. **`EMBEDDINGS_DIMENSIONS` 与预置 FAISS 索引绑定（1536）**：改维度会让辅助 Agent 检索直接 `AssertionError`，且换模型后旧向量不在同一空间。
7. **API 契约变更必须回写** `api/docs/01.项目API文档.md`，否则前端与第三方对接会踩空。

## 10. 子项目：echoMimic（数字人口播视频生成）

> 目录 `echoMimic/`，**独立于主平台**：不在 `docker/docker-compose.yaml` 里、不占 nginx 端口、不起容器，
> 是宿主上手动启动的 Python 项目（需 GPU）。它与主平台的关系是**下游消费方** —— 吃 LLMOps 的文案、吃 TTS 的语音、出数字人视频。

### 10.1 这是什么

蚂蚁集团 / 支付宝终端技术部开源的 **EchoMimic V1**（AAAI 2025，arXiv 2407.08136，上游 `antgroup/echomimic`，
README 自述取自 `BadToBest/EchoMimic`）：**一张人像图 ＋ 一段音频 → 口型与表情同步的说话视频**。

技术路线：Stable Diffusion 底模 ＋ AnimateDiff 的 `motion_module`（时序）＋ **Whisper tiny** 提音频特征 ＋
`face_locator`／MTCNN 定位人脸遮罩；音频（及可选 landmark／姿态）作为可编辑条件送入 `EchoUNet3DConditionModel`，
由 `Audio2VideoPipeline` 分段去噪，最后用 moviepy 把原音轨合回视频。

### 10.2 与主平台的关系（为什么它在这个仓库里）

本项目**改过上游的 `webgui.py`**，加两个按钮，串成一条完整链路：

| 步骤 | 触发 | 实际调用 | 产物 |
|---|---|---|---|
| ① 出文案 | 「获取文案」`fetch_data()` | LLMOps 开放 API `POST {LLMOPS_API_BASE}`（`/api/openapi/chat`），`app_id` + `Bearer` 密钥 | 文本回填「文案内容」框 |
| ② 文案转语音 | 「转换为语音」`text_to_speech()` | 任意 OpenAI 兼容平台的 `audio.speech`：模型 `tts-1`、音色 `alloy`、mp3 | `storage/audio/<uuid>.mp3` |
| ③ 出视频 | 「Generate Video」`process_video()` | 本地扩散推理（`Audio2VideoPipeline`） | `output/tmp/output_video_with_audio.mp4` |

⚠️ **不要用上游同名 `webgui.py` 覆盖本项目的版本** —— ①② 两个按钮与中文界面会丢。

### 10.3 形态与入口

| 入口 | 用途 | 说明 |

| `webgui.py` | Gradio 交互界面 | `--server_port` 默认 **7680**、`--server_name` 默认 `0.0.0.0`，`inbrowser=True` |

### 10.7 硬约束（坑）

1. **显存是硬门槛**：官方验证配置为 V100 16G / 4090D 24G / A100 80G；**本机是 RTX 3070 Ti 8G**。
   默认 `512×512`、`length=1200`、`steps=30` 在这张卡上大概率 OOM —— 先降 `length`／分辨率／`context_frames`，再怀疑代码。
2. **依赖不能随便升级**：`diffusers==0.24.0`、`gradio<=4.44.1`、`torch<=2.2.2`、`huggingface-hub<0.26.0` 全部钉死，
   `src/` 里的 UNet / attention 实现绑 0.24 的 API，升级会直接 import 失败。
3. **权重与 ffmpeg-static 不进仓库**（`.gitignore` 已排除 `pretrained_weights`/`output`/`ffmpeg-4.4-amd64-static`）：
   首次运行必须按 `README.md`「Installation」自行下载，否则 `webgui.py` 一启动就因找不到权重崩溃。
4. **必须有 CUDA**：界面虽有 `Device` 选项，但 `vae`、`face_locator` 等处硬编码 `.to("cuda")`，选 `cpu` 无效。
5. **`.env` 存真实密钥**：提交前确认它已被忽略（`echoMimic/.gitignore` 默认只忽略权重与输出目录，不含 `.env`）。
6. **运行产物目录**：`storage/audio/`、`output/tmp/` 可随时清空；`assets/` 是演示素材，删了批量脚本的 `test_cases` 会找不到文件。

## 11. 子项目：ui-to-code（UI 截图 → HTML 代码）

> 目录 `ui-to-code/`，**与本平台同仓、独立进程**：自己的 `package.json` 与镜像，`npm run dev` 或容器跑在 **3000 / 3001**，
> 不进根 `docker/docker-compose.yaml`、不占 nginx 端口。与主平台的关系同样是**下游消费方** —— 吃 LLMOps 开放 API 的代码产出能力。

### 11.1 这是什么

上传一张 UI 截图，由本平台上的 Agent 生成 HTML 代码、在页面里**实时预览**的网页小工具。面向「不会写前端但想先把画面做出来」的场景。

### 11.2 与主平台的关系（为什么它在这个仓库里）

| 步骤 | 触发 | 实际调用 | 说明 |
|---|---|---|---|
| ① 选图 | 页面选文件 | 浏览器 `FileReader.readAsDataURL` 转 base64 | 只在浏览器里，不上传原图给模型 |
| ② 存图 | `POST /api/upload/image` | 腾讯云 COS `putObject` | 按**真实 MIME** 决定扩展名，返回公网 `image_url` |
| ③ 生成 | `POST /api/chat`（BFF 转发） | 本平台开放 API `${LLMOPS_API_BASE}/chat`（SSE） | 服务端补 `app_id` + `Bearer <api_key>` |
| ④ 预览 | SSE 增量 | 无 | `agent_message.answer` 累加进 `code`，节流写 `iframe.srcdoc` |

⚠️ **图片要真正进模型，两个条件缺一不可**：① 主平台侧多模态能力（`CR-16102701` 已补，`files[].url` 由模型读取）；
② 应用绑定的模型支持视觉输入。任一不满足，URL 只作为文本注入，**模型看不到图**（这就是 `CR-16102700` 的根因与判据）。

### 11.3 形态与入口

- 形态：**网页**，Next.js 15 全栈单体，仅一个页面路由 `/` + 两个 Route Handler（`/api/chat`、`/api/upload/image`）
- 访问：本地 `npm run dev` → `http://localhost:3000`；容器 `docker compose up -d` → `http://localhost:3001`
- 账号：**无登录、无用户体系**，会话靠平台返回的 `end_user_id` / `conversation_id`
- 密钥：全部在服务端环境变量，浏览器只调本项目 `/api/*`，不接触 COS 与平台凭证

### 11.6 环境变量与配置

模板 `ui-to-code/.env.example`，`.env` 不入库（`.gitignore` 用 `.env*` + `!.env.example`）：

| 变量 | 用途 | 配错会怎样 |
|---|---|---|
| `COS_SECRET_ID` / `COS_SECRET_KEY` / `COS_REGION` / `COS_BUCKET` | 存截图并给模型一个公网可读 URL | 上传 500，生成链路断在第一步 |
| `LLMOPS_APP_ID` / `LLMOPS_API_KEY` / `LLMOPS_API_BASE` | 调平台开放 API 产出代码 | `/api/chat` 转发失败，页面停在「代码生成中…」 |

容器里 `LLMOPS_API_BASE` 由 compose 覆盖为 `http://host.docker.internal/api/openapi`（**不改 `.env`**），否则容器内 `localhost` 指向容器自己。

### 11.7 硬约束（坑）

1. **密钥只能出现在服务端**：只在 `src/app/api/**` 读 `process.env`；**不要**给 `COS_*` / `LLMOPS_*` 加 `NEXT_PUBLIC_` 前缀，否则等于把密钥打进浏览器包。
2. **`/api/chat` 必须按 `Content-Type` 分流**：平台可能返回 JSON（出错）、`text/event-stream`、纯 text 三种；只当流处理会在出错时静默卡死。
3. **图片必须先拿到公网 URL 才能进模型**：请求以平台 `files` 传附件（`kind=image` + `url`），**不接受 base64**。
4. **`code` 是流式累加的，写 iframe 必须节流**：直接 `iframe.srcdoc = code` 会每个 chunk 重建文档、页面卡死；`useThrottle(code, 200)` 不能去掉。
5. **`next.config.ts` 的 `images.remotePatterns` 是 `hostname: '*'`**：任意 https 图源都能过 `next/image`，属已知放宽项，收紧前要先确认 COS 域名。
6. **不顺手加依赖 / 不单方面删锁文件**：`package-lock.json` 与 `pnpm-lock.yaml` 并存是既有隐患（已影响容器基础镜像选型）；收敛包管理器或引入测试框架都要开 CR。
7. **容器化后改配置要重建**：`next.config.ts`、`Dockerfile` 改动必须 `docker compose up -d --build`；只 `restart` 不生效。
