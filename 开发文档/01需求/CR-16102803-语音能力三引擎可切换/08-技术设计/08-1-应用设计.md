# CR-16102803 应用设计

## 一、总体结构

```text
                        ┌──────────────────────────────┐
  浏览器                 │  平台设置 →「语音服务」配置项   │
  ├ 录音(MediaRecorder)  │  engine / models / voice / key │
  ├ 播放(SpeechSynthesis)└──────────────┬───────────────┘
  └ 播放(Web Audio PCM)                 │ platform_setting(name=speech_provider)
        │                               ▼
        │  HTTP + SSE        ┌──────────────────────┐
        └──────────────────► │ SpeechProviderService │ 读配置(加密/缓存)
                             └──────────┬───────────┘
                                        │ 按 engine 选 provider
                             ┌──────────▼───────────┐
                             │  AudioService (分发)  │ ← 权限/归属校验(沿用原项目)
                             └──────────┬───────────┘
              ┌─────────────────────────┼─────────────────────────┐
              ▼                         ▼                         ▼
      BrowserProvider            OmniProvider              DashScopeProvider
      (返回"前端执行")        websocket-client → SSC     dashscope SDK
                              (PCM 24k base64)      (CosyVoice TTS / Paraformer ASR)
```

## 二、配置模型

`platform_setting.name = "speech_provider"`，`value` 为 JSON：

```json
{
  "engine": "browser",
  "dashscope_api_key_cipher": "<Fernet 密文>",
  "omni_model": "qwen3.8-omni-flash-realtime",
  "omni_voice": "Aiden",
  "omni_host": "dashscope.aliyuncs.com",
  "cosyvoice_model": "cosyvoice-v3-flash",
  "cosyvoice_voice": "longxiaochun_v3",
  "paraformer_model": "paraformer-realtime-v2"
}
```

- Key 加密复用 `internal/lib/secret.py`（Fernet，主密钥由 `JWT_SECRET_KEY` 派生），**接口永不回显明文**。
- 读取带 **5 秒进程内 TTL 缓存**，保存后 `clear_cache()`（与大模型设置同套路）。
- 库中无配置时回退环境变量 `DASHSCOPE_API_KEY` / `DASHSCOPE_OMNI_HOST`，`engine` 默认 `browser`。

## 三、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/speech-provider` | 读配置（Key 掩码 `****`） |
| `POST` | `/api/speech-provider` | 写配置（`dashscope_api_key` 为空表示不改） |
| `POST` | `/api/speech-provider/test` | 连通性测试（按当前 engine 打一次最小请求） |
| `POST` | `/api/audio/audio-to-text` | 语音转文本（`multipart`，字段 `file`） |
| `POST` | `/api/audio/message-to-audio` | 消息转语音（**SSE**，body `{message_id}`） |

### SSE 契约（与课程原项目一致，前端可复用）

```text
event: tts_message
data: {"conversation_id":"...","message_id":"...","audio":"<base64 PCM>","sample_rate":24000}

event: tts_end
data: {"conversation_id":"...","message_id":"...","audio":""}
```

> 音频统一 **PCM / 16bit / 单声道 / base64**。Omni 为 24000Hz；CosyVoice 请求时指定 22050Hz（`AudioFormat.PCM_22050HZ_MONO_16BIT`）。前端按 `sample_rate` 建 `AudioContext`。

## 四、Provider 抽象

```python
class BaseAudioProvider:
    name: str            # browser / omni / dashscope
    supports_tts: bool
    supports_asr: bool
    def tts_stream(self, text: str) -> Generator[dict, None, None]:
        """yield {"audio": <base64>, "sample_rate": int}"""
    def asr(self, content: bytes, filename: str) -> str:
        """返回识别文本，失败抛业务异常"""
```

- `BrowserProvider`：`tts_stream` 抛 `FailException("当前引擎由浏览器执行")`，由 handler 返回业务提示（AC 里明确要求 200 + `code≠success`）。
- `OmniProvider`：同步 WS。**必须**设 `WS_TIMEOUT=30s`、收尾 `ws.close()`、`response.done` 即止。
- `DashScopeProvider`：`SpeechSynthesizer.call()` 返回**可能为 0 字节**，必须判空抛错（R-02）。

## 五、Omni 时序（关键，照此实现）

```text
客户端                api                 DashScope WS
  │  POST /message-to-audio │                    │
  ├────────────────────────►│                    │
  │                         ├─ 校验消息归属/开关    │
  │                         ├─ ws 连接 ──────────►│
  │                         │◄──── session.created│
  │                         ├─ session.update ───►│ (modalities=text+audio,
  │                         │                    │  turn_detection=null,
  │                         │                    │  instructions=逐字朗读,
  │                         │                    │  output=pcm/24000)
  │                         │◄── session.updated │
  │                         ├─ conversation.item.create(input_text) ──►│
  │                         ├─ response.create ──►│
  │◄── tts_message ─────────┤◄── response.audio.delta (×N)             │
  │        (每块即转发)      │                    │
  │◄── tts_end ─────────────┤◄── response.done   │
  │                         ├─ ws.close() ──────►│
```

约束：
- `turn_detection: null`（不送麦克风音频，纯文本进）。
- `instructions` 固定为「纯朗读器，逐字朗读，不回应、不改写、不加语气词」。
- 累计 `response.audio_transcript.done` 与输入做相似度比对，偏差大记 `warning`（R-05）。

## 六、前端

### 6.1 播放（三路，按 `engine` 分派）

| engine | 实现 | 说明 |
|---|---|---|
| `browser` | `window.speechSynthesis.speak(utterance)` | 零网络；`lang` 取 `zh-CN`；可 `cancel()` 打断 |
| `omni` / `dashscope` | `ssePost` 收块 → `AudioContext({sampleRate})` + `AudioBuffer` 入队 → 顺序播放 | 不用 `MediaSource`（原项目写法），兼容性更好 |

统一出口：`useAudioPlayer()` 返回 `{ loading, isPlaying, play(message_id), stop() }`，`AiMessage.vue` 只认这三个。

### 6.2 录音（按 `engine` 分派）

| engine | 实现 |
|---|---|
| `browser` | 沿用现有 `webkitSpeechRecognition`（不改） |
| `omni` | 同上（本档不提供服务端 ASR，见 D-08） |
| `dashscope` | **Web Audio 采集 → 自行封装 16k/16bit/单声道 WAV** → `POST /audio/audio-to-text` → 回填输入框 |

> ⚠️ **不能**用 `MediaRecorder`：Chrome 只能产 `audio/webm`，而 Paraformer 不支持 webm 容器（D-12）。
> ⚠️ 录音需安全上下文：非 HTTPS / 非 localhost 时 `getUserMedia` 会被拒，前端置灰并提示原因（R-08）。


### 6.3 组件

- `SettingModal.vue`：新增「语音服务」菜单项与面板，`data-testid="setting-menu-speech-provider"`。
- `AiMessage.vue`：加播放/暂停按钮，`data-testid="message-tts-play"`。
- `ChatInputBar.vue`：麦克风按 engine 分支，`data-testid="chat-input-mic"`。
- `TextToSpeechAbilityItem.vue` / `SpeechToTextAbilityItem.vue`：应用级开关，写 `draft_app_config`。
- `AgentAppAbility.vue`：挂两个折叠项。

## 八、错误处理约定

| 场景 | HTTP | `code` | `message` |
|---|---|---|---|
| 未配置 Key | 200 | `fail` | 语音服务未配置，请在「设置 → 语音服务」填写阿里百炼 API Key |
| 引擎为 browser 却调后端接口 | 200 | `fail` | 当前引擎由浏览器执行，无需调用服务端语音接口 |
| 合成返回 0 字节 | 200 | `fail` | 语音合成失败（模型或音色不可用），请检查引擎配置 |
| WS 超时 / 断连 | 200 | `fail` | 语音服务连接超时，请稍后重试 |
| 消息不属于当前用户 | 404 | `not_found` | 该消息不存在，请核实后重试 |
| 应用未开启 TTS | 200 | `fail` | 该应用未开启文字转语音功能，请核实后重试 |

> 一律不用 5xx（`00规则/开发规范.md` §五：错误路径明确返回值）。
