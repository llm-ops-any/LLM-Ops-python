# 项目概述

> **本文件是「入场地图」**：让第一次进入项目的人和 agent 在 5 分钟内知道
> 「这是什么、用什么做的、怎么跑起来、改哪里、别踩哪些坑」。
> 由人维护，agent 可提修改建议但**不得自行扩写**。
>
> **边界（重要）**：本文件只写**稳定骨架**——定位、形态、技术栈、拓扑、目录、链路、外部依赖、硬约束。
> **不写**：进度、待办、CR 列表、决策理由、谁负责什么。
> 那些各有归属：进度 → 各 `CR-XXXX/状态.md`；决策 → `CR-XXXX/决策记录.md`；全局视图 → `_汇总/`；
> 审批模式与角色 → `00规则/团队配置.md`。**在本文件里写进度的唯一后果是它很快过期，然后没人再信它。**
>
> 依据：2026-10-16 对仓库逐文件核查 + 2026-10-26 初始化时复核依赖与目录。数字类结论标了统计日期。

## 1. 一句话定位

一个**类 Dify 的「AI 应用开发平台」**：用户在网页上创建 AI 应用 → 编排提示词 / 挂工具与知识库 →
调试 → 发布成 **WebApp**（对外链接）或**开放 API**（给第三方程序调）。
平台自身另带：**工作流编排**（可视化拖拽 8 类节点）、**知识库 RAG**、**模型供应商管理**、**内置应用与插件广场**。

## 2. 交付物形态

- **网页平台**：本机自用部署，对外**只暴露 80**（nginx 唯一入口），其余端口绑 `127.0.0.1`。
- **WebApp 链接**：发布态应用可被外部访问的独立页面。
- **开放 API**：第三方按 key 调用；配套 `api/docs/01.项目API文档.md` 为接口契约，**改接口必须回写**。
- 无对外 SaaS 形态，不是库、不是桌面程序。

## 4. 运行时拓扑

编排文件 `docker/docker-compose.yaml`，全部服务在同一 Docker 网络：

| 组件 | 宿主端口 | 职责 |
|---|---|---|
| `llmops-nginx` | **80（唯一对外）** | 反代 ui 与 api |
| `llmops-ui` | `127.0.0.1:3000` | 前端（Vite 构建产物） |
| `llmops-api` | `127.0.0.1:5001` | Flask + gunicorn；**启动时负责跑 alembic 迁移** |
| `llmops-celery` | 无 | Celery worker（文档索引等异步任务） |
| `llmops-db` | `127.0.0.1:5432` | PostgreSQL 15，业务库 `llmops` |
| `llmops-redis` | `127.0.0.1:6379` | 缓存 / Celery broker / Agent 队列停止标记 |
| `llmops-weaviate` | `127.0.0.1:8080`、`50051` | 向量库 |

要点：**api 与 celery 是同一个镜像**，靠环境变量 `MODE`（`api`/`celery`）在 `docker/entrypoint.sh` 分流；
迁移只由 api 跑（`MIGRATION_ENABLED=true`，celery 为 `false`），避免重复执行。
数据全在 `docker/volumes/`（`db/data`、`redis/data`、`weaviate/`、`app/storage`）—— **清目录＝清数据**。

## 6. 核心链路

1. **应用编排 → 调试 → 发布**：`router` → `handler` → `service`（应用/会话/消息）→ `core/agent`（LangGraph）→
   模型调用（统一中转平台）＋ 工具调用 ＋ 检索；发布后由 WebApp handler / 开放 API handler 复用同一条 invoke 链路。
2. **知识库 RAG**：上传文件（落 COS / 本地 storage）→ `handler` 建 `Dataset` 记录 → **Celery 异步**切分与索引
   → 向量应用侧算好后写入 Weaviate `Dataset` collection → 检索时按 `RetrievalService` 召回注入提示词。
3. **工作流**：前端 vue-flow 拖拽生成图 → 后端 `core/workflow` 按 8 类节点（开始/结束/LLM/工具/知识库检索/代码/分支等）
   顺序执行 → 结果回写会话。
4. **鉴权**：`middleware/request_loader` 按来源分流（平台登录态 / WebApp token / 开放 API key）。

## 7. 外部依赖

> **只写服务名与用途，绝不写凭证值。** 凭证放 `docker/.env`（兜底）或平台设置页（落库密文，优先），不入库明文、不进 `开发文档/`。
> 每项「不配会怎样」详见 `环境变量配置说明.md`。

| 依赖 | 用途 | 配错会怎样 |
|---|---|---|
| 模型统一中转平台（OpenAI 兼容） | 所有 LLM / 向量 / 重排调用；凭证可在「设置 → 大模型设置」维护，库内密文、优先于 `.env` | 应用可建但一调试就失败 |
| 腾讯云 COS | 文件与图片存储 | 知识库上传、头像等报错 |
| GitHub OAuth | 平台登录 | 无法登录后台 |
| 高德 | 内置工具（天气/地图类） | 该工具调用失败 |
| Serper | 联网搜索工具 | 搜索类工具不可用 |
| LangSmith | 调用链追踪 | 仅影响可观测性 |
| 本地设施（db / redis / weaviate） | 业务数据 / 队列 / 向量 | 服务起不来或迁移失败 |

## 8. 硬约束（踩过的坑）

1. **后端代码与模型 YAML 烘焙进镜像**：改完必须 `docker compose build llmops-api` 再 `up -d`，
   `docker compose restart` 不够 —— 否则「改了没生效」，白查半天。
2. **不硬编码官方模型名**（`gpt-4o-mini` 那类）：本项目的模型全部走中转平台，官方名在平台上不存在，
   模型清单以 `api/internal/core/language_model/providers/**/*.yaml` 为准。
3. **Weaviate 向量化模块关闭**（`DEFAULT_VECTORIZER_MODULE: 'none'`）：向量必须由应用侧算好再写入，
   别指望向量库自动向量化。
4. **表结构变更只走 alembic**（`api/internal/migration/`），且只有 api 容器执行迁移；手改库会导致下轮迁移失败。
5. **`docker/volumes/` 是真实数据**，`docker compose down -v` 或清理目录 = 数据全没。
6. **密钥只放 `docker/.env`（兜底）或平台设置页（库内 Fernet 密文）**，不进仓库、不进 `开发文档/`、不进审计记录、不进日志。
7. **向量化必须 `check_embedding_ctx_length=False`**：langchain 默认先把文本 tiktoken 分词成整数数组再发送，
   中转平台只接受字符串，会报 `contents is neither str nor list of str`。早期把这个 400 误判成「阿里模型与 langchain 不兼容」，
   导致错换成不可用的 `qwen3-embedding-8b`（503）。当前正确组合：`text-embedding-v4` + `EMBEDDINGS_DIMENSIONS=1536`。
8. **`EMBEDDINGS_DIMENSIONS` 与预置 FAISS 索引绑定（1536）**：改维度会让辅助 Agent 检索直接 `AssertionError`，且换模型后旧向量不在同一空间。
7. **API 契约变更必须回写** `api/docs/01.项目API文档.md`，否则前端与第三方对接会踩空。
